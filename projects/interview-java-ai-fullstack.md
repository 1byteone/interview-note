# 第一部分：Java 微服务架构（1-6）

### 题目 1：微服务拆分原则是什么？【简答】

**考察点**：架构设计能力

**答案**：
1. **高内聚低耦合**：每个服务只负责一个业务域
2. **数据独立**：每个服务拥有独立数据库
3. **接口契约**：通过 OpenFeign/API 定义交互
4. **团队自治**：服务可由独立团队开发部署

---

### 题目 2：你为什么用单体……不对，你们项目为什么用微服务？【场景】

**考察点**：技术选型决策能力

**答案**：
- 电商业务天然分为用户/商品/订单/库存/支付等独立领域
- 需要独立扩展（如秒杀服务单独扩容）
- 团队并行开发互不阻塞
- 技术栈可异构（库存服务可用 Redis 优化）

---

### 题目 3：你们 11 个微服务怎么保证数据一致性？【场景】

**考察点**：分布式一致性问题

**答案**：
| 场景 | 方案 |
|------|------|
| 下单+扣库存 | Seata AT 分布式事务 |
| 秒杀 | Redis 预扣 + MQ 异步 + 乐观锁 |
| 订单支付回调 | 消息最终一致性 + 幂等 |
| 购物车 | MongoDB 单库（无跨服务） |

---

### 题目 4：单体架构和微服务如何选型？【简答】

**考察点**：架构权衡

**答案**：
- **团队 < 10 人 / 业务简单**：优先单体
- **业务复杂 / 需独立扩展 / 多团队协作**：微服务
- **不要为了微服务而微服务**：微服务带来分布式复杂度（网络/事务/运维）

---

### 题目 5：你们项目启动要依赖哪些中间件？【简答】

**考察点**：中间件综合理解

**答案**：
| 中间件 | 用途 |
|--------|------|
| Nacos | 服务注册 + 配置中心 |
| MySQL | 业务数据存储 |
| Redis | 缓存/分布式锁/幂等 |
| RocketMQ | 消息异步解耦 |
| Elasticsearch | 商品搜索 |
| MongoDB | 购物车存储 |

---

### 题目 6：微服务的服务治理包含哪些？【简答】

**考察点**：服务治理体系

**答案**：
1. 服务注册发现（Nacos）
2. 负载均衡（LoadBalancer）
3. 流量控制（Sentinel 限流）
4. 熔断降级（Sentinel）
5. 分布式事务（Seata）
6. 链路追踪（SkyWalking）
7. 统一网关（Gateway）

# 第二部分：Nacos 服务注册与配置（7-10）

### 题目 7：Nacos 的核心功能有哪些？【简答】

**答案**：
1. **服务发现**：服务注册、健康检查、负载均衡
2. **配置管理**：配置中心、动态刷新、命名空间隔离
3. **命名空间**：环境隔离（dev/prod）

---

### 题目 8：Nacos 动态刷新配置的原理？【简答】

**答案**：
1. 客户端发起**长轮询**请求
2. 服务端挂起请求（最长 30s）
3. 配置变更时立即响应
4. 客户端拉取最新配置
5. `@RefreshScope` 重新注入 Bean

---

### 题目 9：Nacos 集群部署有哪些注意事项？【场景】

**答案**：
1. 至少 3 节点
2. 共享 MySQL 做持久化
3. Nginx 做负载均衡接入
4. 命名空间区分环境

---

### 题目 10：Nacos 挂了服务还能用吗？【场景】

**答案**：
- **能**：客户端有本地缓存（snapshot 目录缓存配置、注册信息）
- 已注册服务间的调用不受影响
- 但新服务注册/配置变更会失败

# 第三部分：Gateway / OpenFeign（11-15）

### 题目 11：Gateway 和 Zuul 的区别？【简答】

**答案**：
| 特性 | Gateway | Zuul 1.x |
|------|---------|----------|
| 底层 | WebFlux（Reactor 响应式） | Servlet（阻塞 IO） |
| 异步 | 原生支持 | 不支持 |
| 性能 | 高 | 低 |
| 长连接 | WebSocket 支持 | 不支持 |

---

### 题目 12：Gateway 过滤器链的执行顺序？【简答】

**答案**：
```
请求 → Pre Filter（鉴权/限流/改写）→ 转发到服务
                                       ↓
响应 ← Post Filter（日志/错误处理/改写）
```

---

### 题目 13：OpenFeign 底层实现原理？【简答】

**答案**：
1. `@EnableFeignClients` 扫描 FeignClient 接口
2. 通过 JDK 动态代理生成接口实现
3. `InvocationHandler` 拦截方法调用
4. 解析注解生成 HTTP 请求
5. LoadBalancer 选择实例
6. HTTP 发请求 + 解码响应

---

### 题目 14：OpenFeign 如何配置超时和重试？【场景】

**答案**：
```yaml
feign.client.config.default:
  connectTimeout: 5000
  readTimeout: 10000

# 重试
@Bean
public Retryer feignRetryer() {
    return new Retryer.Default(100, 1000, 3); // 最多重试3次
}
```

---

### 题目 15：Gateway 如何实现限流？【场景】

**答案**：
1. `RequestRateLimiter` 过滤器
2. Redis Lua 脚本令牌桶
3. `KeyResolver` 按用户/IP 分流

# 第四部分：Sentinel 限流熔断（16-19）

### 题目 16：Sentinel 限流有哪些策略？【选择】

A. 直接拒绝、预热、匀速排队
B. 固定窗口、滑动窗口
C. 漏桶、令牌桶
D. 以上都是

**答案**：A（Sentinel 策略是直接拒绝/预热/匀速排队；C 是限流算法的底层实现）

---

### 题目 17：Sentinel 熔断降级的原理？【简答】

**答案**：
1. 熔断状态机：CLOSED → OPEN → HALF_OPEN
2. 触发条件：慢调用比例/异常比例/异常数
3. 熔断后快速失败，降级返回
4. 半开状态探测恢复

---

### 题目 18：Sentinel 和 Hystrix 的区别？【简答】

**答案**：
| 特性 | Sentinel | Hystrix |
|------|----------|---------|
| 流量控制 | 丰富（QPS/线程/预热） | 有限 |
| 熔断策略 | 慢调用/异常比例/异常数 | 仅异常比例 |
| 动态规则 | 支持（Nacos 持久化） | 不支持 |
| 系统保护 | 自适应 | 不支持 |

---

### 题目 19：Sentinel 规则如何持久化？【场景】

**答案**：
- 默认内存存储，重启丢失
- 通过 DataSource 扩展接入 Nacos
- 规则存 Nacos → Sentinel 动态读取

# 第五部分：Seata 分布式事务（20-22）

### 题目 20：Seata AT 模式的原理？【简答】

**答案**：
```
一阶段：业务 SQL 直接提交 + 生成前后镜像写 undo_log
二阶段-提交：删除 undo_log
二阶段-回滚：根据 undo_log 生成反向 SQL 恢复数据
```

---

### 题目 21：AT、TCC、Saga、XA 如何选择？【选择】

**考察点**：分布式事务方案选型

**答案**：
| 场景 | 方案 |
|------|------|
| 常规业务 | AT（侵入小，推荐） |
| 资金/强一致 | TCC |
| 长链路 | Saga |
| 强一致低性能 | XA |

---

### 题目 22：你们项目哪些场景需要分布式事务？【场景】

**答案**：
- 订单服务 + 商品服务跨服务下单（Seata AT）
- 秒杀场景用 MQ 最终一致性（不适用强一致）
- 支付回调 + 订单状态更新（MQ 异步）

# 第六部分：RocketMQ 消息队列（23-26）

### 题目 23：如何保证消息不丢失？【简答】

**答案**：
| 阶段 | 方案 |
|------|------|
| 生产 | 同步发送 + 重试 + acks=all |
| Broker | 同步刷盘 + 主从复制 |
| 消费 | 消费成功才提交 offset |

---

### 题目 24：消息重复消费如何解决？【场景】

**答案**：
1. **Redis 幂等锁**：`setIfAbsent(msgId, 1, 30s)`
2. **数据库唯一约束**：唯一索引防重
3. **业务状态机**：只处理特定状态

---

### 题目 25：RocketMQ 事务消息的原理？【简答】

**答案**：
```
① 发送半消息（prepare）
② 执行本地事务
③ 提交/回滚消息
④ 若超时未确认，反查本地事务状态
```

---

### 题目 26：消息堆积如何处理？【场景】

**答案**：
1. 增加消费者 + 分区
2. 批量消费（consumeMessageBatchMaxSize）
3. 异步处理耗时逻辑
4. 排查消费者性能瓶颈

# 第七部分：Hybrid RAG 检索增强（27-32）

### 题目 27：什么是 Hybrid RAG？为什么用混合检索？【简答】

**答案**：
- Hybrid RAG = 向量检索 + 关键词检索（BM25）+ 图检索 多路召回
- 向量检索擅长语义相似，关键词检索擅长精确匹配
- 单一检索召回不全，混合互补

---

### 题目 28：RRF 融合算法的原理？为什么不用加权平均？【简答】

**答案**：
```
RRF 公式：score(doc) = Σ 1/(k + rank_i)
```
- RRF 对**排名**敏感，对分数不敏感
- 不同检索器的分数尺度不同（余弦 0-1、BM25 0-100），直接加权没有意义
- RRF 天然鲁棒，无需调权重

---

### 题目 29：向量检索和 Reranker 有什么区别？【简答】

**答案**：
| 特性 | 向量检索（双编码器） | Reranker（交叉编码器） |
|------|---------------------|----------------------|
| 原理 | query 和 doc 分别编码 | query+doc 拼接输入 |
| 交互 | 无（各自独立编码） | 有（完整交互） |
| 速度 | 快（预计算索引） | 慢（逐对计算） |
| 精度 | 一般 | 更准 |
| 定位 | 召回（第一层） | 精排（第二层） |

---

### 题目 30：如何评估 RAG 系统效果？【简答】

**答案**：
| 指标 | 说明 |
|------|------|
| Recall@K | 相关文档是否被召回 |
| Precision@K | 召回的准确率 |
| MRR / NDCG | 排序质量 |
| 忠实度 | 回答是否忠于文档 |
| 幻觉率 | 是否有编造内容 |

---

### 题目 31：如何控制 RAG 的幻觉（LLM Hallucination）？【场景】

**考察点**：AI 落地实战（对应项目 Domain Guard + 证据门控）

**答案**：
1. **检索过滤**：Domain Guard 领域守卫，拒绝非领域问题
2. **证据门控**：低置信度证据不放行
3. **提示词工程**：要求"知识库没有明确说不知道"
4. **输出验证**：引用溯源 + 高风险来源闸门（只有 A 级来源才能支撑剂量/政策结论）
5. **分级来源**：A/B/C/D 四级来源登记

---

### 题目 32：项目的 RAG 检索流程是什么？【场景】

**考察点**：项目深挖（对应 CropWise）

**答案**：
```
用户问题 → Multi-Query 分解 → 并行检索（Vector/BM25/Graph）
→ RRF 融合 → BGE-Reranker 精排 → 证据门控 → LLM 生成 → SSE 流式
```

# 第八部分：LangGraph / Agent（33-36）

### 题目 33：LangGraph 和 LangChain 的区别？【简答】

**答案**：
- LangChain：线性 DAG 链式调用
- LangGraph：基于图的状态编排，支持**循环**和**条件分支**
- Agent Loop（推理→行动→观察）需要循环，LangChain 无法自然表达

---

### 题目 34：什么是 Agent Loop（ReAct）？【简答】

**答案**：
```
Thought（思考）→ Action（调用工具）→ Observation（观察结果）→ 循环直到完成
```

---

### 题目 35：6 个 Agent 工具如何设计？【设计】

**考察点**：工具设计能力（对应 CropWise）

**答案**：
| 工具 | 作用 |
|------|------|
| query_crop_knowledge | 作物知识检索 |
| get_current_datetime | 当前时间（农时计算） |
| calculate_growing_period | 生育期计算 |
| get_agri_weather | 农业气象 |

### 题目 36：Agent 工具调用失败怎么办？【场景】

**答案**：
1. 工具返回错误信息 → LLM 重试或换工具
2. 设置最大迭代次数防死循环
3. 记录工具审计日志（耗时/成败）
4. 降级：返回通用建议而非编造

# 第九部分：知识图谱 / GraphRAG（37-38）

### 题目 37：知识图谱在 RAG 中起什么作用？【简答】

**答案**：
- 向量检索：语义相似但**缺乏结构化推理**
- 知识图谱：实体-关系结构，支持**多跳推理**（如：水稻 → 病虫害 → 防治方法）
- GraphRAG：将知识图谱与 RAG 结合，弥补向量检索的结构化缺失

---

### 题目 38：Docker 部署 Neo4j 要注意什么？【场景】

**答案**：
1. 数据持久化：挂载 volume（`neo4j_data:/data`）
2. 认证：NEO4J_AUTH 环境变量
3. 插件：APOC 等需要 NEO4J_PLUGINS
4. 性能：合理配置堆内存/page cache

# 第十部分：SSE 流式响应（39-40）

### 题目 39：SSE 和 WebSocket 的区别？【简答】

**答案**：
| 特性 | SSE | WebSocket |
|------|-----|-----------|
| 方向 | 单向（服务端→客户端） | 双向 |
| 协议 | HTTP | 独立协议 |
| 自动重连 | 原生支持 | 需自己实现 |
| 适用 | 服务端主动推送 | 实时双向通信 |

---

### 题目 40：前后端 SSE 对接要注意什么？【场景】

**答案**：
后端：
- 响应头：`Content-Type: text/event-stream`、`Cache-Control: no-cache`
- 禁用缓冲：`X-Accel-Buffering: no`
- 事件格式：`event: type\ndata: {json}\n\n`

前端：
- fetch + ReadableStream 分块读取
- TextDecoder 解码
- 断线自动重连
