## 🎯 Level 1：基础题

### 1. Nacos 是什么？核心功能有哪些？
**答案**：
Nacos（Dynamic Naming and Configuration Service）是阿里巴巴开源的**动态服务发现、配置管理和服务管理平台**。

**两大核心功能**：
1. **服务注册与发现**：服务启动时向 Nacos 注册，消费者从 Nacos 获取服务实例列表
2. **配置管理**：集中管理配置，支持动态刷新（配置变更实时推送）

**应用方式**：是 Spring Cloud Alibaba 生态的核心组件，替代 Eureka + Spring Cloud Config。

### 2. Nacos 与 Eureka 的区别？
**答案**：

| 特性 | Nacos | Eureka |
|------|-------|--------|
| 功能 | 注册中心 + 配置中心 | 仅注册中心 |
| 一致性 | 支持 AP + CP | 仅 AP |
| 健康检查 | 主动检测 + 心跳 | 仅心跳（30s） |
| 负载均衡 | 权重 + 保护阈值 | 不支持 |
| 动态配置 | 支持 | 不支持 |
| 协议 | Distro / Raft | 自身协议 |
| 维护 | 阿里维护，活跃 | Netflix 停止新功能 |

## 🎯 Level 2：进阶题

### 3. 服务注册与发现的原理是什么？
**答案**：

```text
服务提供者(Provider)
    │  ① 启动时注册 (register)
    │  ② 发送心跳 (beat) 每 5s
    ▼
┌─────────────────┐
│      Nacos      │
│ 服务注册表(SV)  │
└─────────────────┘
    ▲
    │  ① 启动时订阅 (subscribe)
    │  ② 拉取实例列表
服务消费者(Consumer)
```

**注册流程**：
1. 服务提供者通过 OpenFeign/Dubbo 向 Nacos 注册服务
2. 注册信息包含：服务名、IP、端口、权重、元数据
3. Nacos 维护服务注册表，提供者每 5 秒发送心跳
4. 消费者通过 `@LoadBalanced` + Ribbon 从 Nacos 拉取并轮询调用

**健康检查机制**：
- 临时实例：心跳续约，超过 15 秒未心跳标记不健康，30 秒剔除
- 持久实例：Nacos 主动 `TCP/HTTP` 探测

### 4. Nacos 配置中心的动态刷新原理？
**答案**：

**核心：长轮询（Long Polling）机制**

```text
客户端发起长轮询请求
    ↓
服务端挂起请求（最长 30s）
    ↓
配置变更
    ├── 立即响应变更内容
    ↓
客户端更新配置
    ↓
触发 @RefreshScope 刷新 Bean
```

**具体流程**：
1. `@NacosValue` / `@RefreshScope` 标记的配置由 Nacos Config 管理
2. 客户端启动时拉取配置并建立长轮询
3. Nacos 服务端检测到配置变更时，立即返回响应
4. 客户端收到通知后重新拉取配置，触发 Bean 刷新

### 5. 什么是临时实例和持久实例？
**答案**：

| 特性 | 临时实例（默认） | 持久实例 |
|------|-----------------|----------|
| 健康检查 | 心跳（5s） | 服务端主动探测 |
| 宕机处理 | 超时剔除 | 标记不健康 |
| 适用场景 | 微服务（AP） | 数据库、网关（CP） |
| 注册方式 | 默认 | `ephemeral=false` |

## 🎯 Level 3：高级题

### 6. Nacos 集群如何部署？数据一致性如何保证？
**答案**：

**集群部署模式**：
```
      Nginx（负载均衡）
    ┌────┼────┐
    ↓    ↓    ↓
Nacos-1 Nacos-2 Nacos-3
    └────┴────┘
     MySQL（默认）→ 持久化
```

**三种部署模式**：
1. **单机模式**：`standalone`，内置 Derby
2. **集群模式**：3 节点 + 共享 MySQL（生产推荐）
3. **多集群模式**：多地域容灾

**一致性协议**：
- **临时实例（AP）**：Distro 协议，最终一致性
- **持久实例 + 配置（CP）**：Raft 协议，强一致性

### 7. Nacos 与 Spring Cloud 其他组件的集成原理？
**答案**：

**与 Gateway 集成**：
- 服务路由：通过 `lb://service-name` 动态路由到 Nacos 注册的服务
- 动态路由：路由配置可在 Nacos 配置中心动态刷新

**与 OpenFeign 集成**：
- Feign 通过 Nacos Discovery + LoadBalancer 获取实例
- 实现远程调用的服务发现与负载均衡

**与 Sentinel 集成**：
- Sentinel Dashboard 注册到 Nacos
- 限流规则存储在 Nacos 配置中心，动态下发

## 🎯 Level 4：专家题

### 8. Nacos 作为注册中心为什么选择 AP？配置中心为什么选 CP？
**答案**：
**注册中心（AP，最终一致性）**：
- 服务注册允许短暂不一致（新实例没被立刻发现）
- 追求可用性：注册中心挂一个节点系统仍可用
- 符合微服务"容忍最终一致"的需求

**配置中心（CP，强一致性）**：
- 配置强调强一致：同一个配置在所有节点必须一致
- 配置不一致会导致系统行为不一致
- 使用 Raft 协议保证强一致性

### 9. Nacos 服务发现与配置中心的高可用如何设计？
**答案**：
```
客户端 → LVS/F5 → Nginx → Nacos三节点
                        → MySQL主从（配置/持久化）
                        → 异地容灾（多集群）
```

**HA 策略**：
1. 客户端本地缓存：Nacos 不可用时使用本地缓存（目录）
2. 故障转移：Fail-Fast + 重试
3. 数据持久化：配置写入 MySQL，防止 Nacos 重启丢失
4. 双集群容灾：异地多活
