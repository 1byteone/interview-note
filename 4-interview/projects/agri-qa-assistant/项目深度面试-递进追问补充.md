# 农业知识库问答智能体（CropWise）—项目深度面试递进追问补充

> 本文是独立补充稿，不修改原有文档。所有“优化方向”必须在面试中明确说明为后续计划。
>
> **事实基线**：FastAPI + LangGraph Agent + Next.js 14；ChromaDB、BGE-M3、BM25、RRF、BGE-Reranker、Neo4j；支持文档摄入、领域守卫、会话记忆和流式回答；项目独立完成。当前材料记录：知识库准确率 85%+、幻觉率由 40%+ 降至 5%、首字响应约 200ms、并发用户 100+。

## 一、项目 STAR 总述

> **S**：农业技术资料分散在 PDF、DOCX 和网页中，农户的问题往往包含作物、病害、时期和处置条件，纯通用大模型容易产生看似合理但不适用于本地农业的回答。
>
> **T**：我独立完成从文档解析、切分、向量化、混合检索、知识图谱到 Agent 流式问答的闭环，并降低无依据回答。
>
> **A**：用领域守卫拦截非农业问题；向量、BM25 和 Neo4j 多路召回后用 RRF 融合，再用 BGE-Reranker 精排；把证据注入 Prompt，后处理校验引用和结构化输出；用 LangGraph 编排路由、工具调用和记忆。
>
> **R**：在现有测试口径下，知识库问答准确率达到 85%+，幻觉率由 40%+ 降至 5%，首字响应约 200ms。后续仍需扩大标注集、建立自动评估和生产级多租户隔离。

## 二、LangGraph 与 Agent 递进追问

### Q1：为什么不用一个简单的 RAG Chain？

简单链适合“检索后回答”，但 CropWise 需要领域判断、查询路由、多个工具、会话记忆和失败分支。LangGraph 用显式状态和节点表达流程，可观察、可重试，也能控制哪些工具允许执行。代价是状态契约和分支测试更复杂。

### Q2：Agent 的状态包含什么？为什么不能随意塞对象？

状态至少包含用户问题、thread_id、路由结果、检索候选、最终证据、工具结果和错误信息。状态应尽量使用可序列化、边界清晰的数据结构，避免把数据库连接、请求对象或不可复现的对象放入状态，否则难以持久化、重试和调试。

### Q3：工具调用如何避免失控？

工具需要白名单注册、参数 schema 校验、超时、调用次数上限和错误包装。网页抓取、天气 API 等外部工具还要限制 URL、响应大小和重定向；工具返回结构化结果，不直接把异常堆栈交给模型。Agent 只能在允许的节点调用工具，不能让模型自由执行任意代码。

### Q4：领域守卫为什么不能只靠关键词？

关键词表成本低、响应快，适合第一层过滤，但会误伤“农业新闻中的金融词”，也会漏掉没有术语的新问题。因此领域守卫可采用术语规则 + 分类模型/LLM 二次判断 + 低置信度转人工或澄清。当前术语表是实用的第一道防线，不应声称能解决全部语义判断。

## 三、Hybrid RAG 深挖

### Q5：为什么要向量检索和 BM25？

向量检索擅长语义近似，例如“叶片发黄”与“黄化”；BM25 擅长精确命中作物名、病害名、药剂名和型号。农业场景同时需要语义召回和专业词精确召回，混合检索比单一路径更稳。

### Q6：RRF 解决什么问题？

不同召回器的分数不可直接比较，向量距离、BM25 分数和图查询结果没有统一量纲。RRF 根据候选排名计算倒数排名贡献，再融合各路结果，减少分数归一化依赖。它简单稳健，但没有利用每个召回器的分数质量；后续可通过验证集学习权重。

### Q7：为什么还需要 Reranker？

多路召回解决“不要漏掉相关证据”，Reranker 解决“把最相关证据排到前面”。交叉编码器同时看 query 和文档，语义判断通常比单独 embedding 相似度细。代价是计算慢，因此先召回 Top-K，再精排较小候选集。

### Q8：如何选择 chunk 大小 512 token？

太小会丢失病害症状、作物阶段和处置方法之间的关系，太大会引入无关内容并降低召回精度。512 是在语义完整、上下文长度和检索粒度之间的折中；应通过 chunk 长度实验、召回率、答案引用准确率共同验证，而不是把 512 当通用定律。

### Q9：知识库没有答案时，如何防止模型编造？

检索结果低于阈值或证据互相矛盾时，回答应明确“资料不足”，请求补充作物、地区、症状或图片；不能强行生成确定处方。Prompt 要求只依据证据，后处理检查引用；高风险农药建议应提示遵循标签和当地规范。

### Q10：为什么相似度阈值 0.6 不能直接迁移？

不同 embedding 模型、文本长度、数据分布和距离度量会改变分数分布。阈值应在标注验证集上统计 precision/recall，并区分不同问题类型。当前 0.6 来自小规模手工测试，属于项目参数，不是行业通用标准。

## 四、向量库、图谱与数据一致性

### Q11：为什么 Neo4j 与向量库同时存在？

向量库适合语义相似检索，Neo4j 适合表达“作物—病害—症状—药剂—生长阶段”等关系并做多跳查询。图谱可以补充结构化关系证据，但需要实体消歧、关系质量和更新维护；不能因为用了图数据库就自动获得准确知识。

### Q12：文档更新后，如何保证向量、BM25 和图谱一致？

为文档生成版本号和内容 hash，摄入任务按“解析—切分—向量索引—全文索引—图谱抽取”记录状态。任一步失败可重试，旧版本保留到新版本校验完成再切换；定期做文档清单与索引清单对账，避免只更新一种索引。

### Q13：为什么 ChromaDB 适合当前项目，何时不适合？

它部署轻、开发成本低，适合独立项目和中小规模知识库。数据量、并发写入、HA、权限和多租户要求提高后，应评估 PostgreSQL + pgvector、Milvus 或 Elasticsearch 等方案。迁移前要抽象 embedding、collection 和检索接口，避免业务代码绑定具体向量库。

## 五、文档摄入与质量

### Q14：PDF 切分最难的地方是什么？

PDF 的版面不是天然语义结构，表格、页眉页脚、断行和 OCR 错误会破坏上下文。摄入应记录来源文件、页码、标题、章节和 chunk 顺序，清洗不能盲目删除换行；对表格和图片信息应单独处理，并支持失败重试和人工抽检。

### Q15：如何判断文档已经成功入库？

不能只看向量条数。应校验文件 hash、chunk 数量、embedding 维度、元数据完整性、BM25 可查性、图谱实体关系和抽样召回结果。摄入任务设置 `PENDING/RUNNING/SUCCESS/FAILED`，前端展示失败原因和可重试入口。

## 六、会话记忆、SSE 与性能

### Q16：thread_id 如何隔离会话？

每次请求携带 thread_id，服务端查询对应消息并注入上下文；必须同时校验 thread_id 所属 user_id，不能让用户通过修改 ID 读取他人会话。SQLite + FTS5 适合当前规模，但高并发和多实例部署时需要共享数据库、连接池和迁移方案。

### Q17：为什么用 SSE？和 WebSocket 怎么选？

问答主要是服务端单向持续输出，SSE 基于 HTTP、浏览器接入简单，适合 token 流；WebSocket 更适合双向实时协作，但连接治理更复杂。SSE 必须处理断开、心跳、代理缓冲、超时和重复订阅；客户端重连需要 event id 或任务状态，不能简单重复生成。

### Q18：首字 200ms 如何测量？

从服务端接收请求开始，到客户端真正收到第一个可展示事件结束，区分缓存命中、模型连接建立和模型首 token；记录平均值与 P95，并固定网络和数据集。不能用“开始调用模型的时间”冒充用户看到首字的时间。

## 七、安全与评估

### Q19：Prompt 注入如何防护？

检索文档和网页内容都属于不可信输入，不能把其中“忽略系统要求、执行命令”等文字当指令。通过系统提示与用户/文档内容分隔、工具白名单、输出 schema、敏感操作确认和内容长度限制降低风险；模型安全措施不能替代服务端权限校验。

### Q20：如何评估 RAG，不只看准确率？

建立带标准答案和证据页码的测试集，分别评估召回 Recall@K、MRR、NDCG、上下文 precision、答案 faithfulness、引用正确率、拒答准确率、首字延迟和完整响应时间。还要按作物、病害、复杂度和无答案问题分层，避免平均分掩盖薄弱场景。

### Q21：幻觉率从 40% 降到 5% 怎么证明？

必须说明样本数量、问题构成、判定标准、是否同一模型和同一测试集。由多人或规则+人工复核标注，区分“事实错误”“无证据扩展”和“表达不完整”。如果只是小样本手工测试，应说“在当前测试集上”，不能泛化为生产幻觉率。

## 八、故障与演进题

1. **Embedding API 不可用**：保留任务失败状态和重试，不要悄悄混用不同维度向量；必要时使用已部署的同维度回退模型。
2. **Neo4j 不可用**：对不依赖图关系的问题使用向量/BM25，明确降低能力；不能返回不存在的关系。
3. **LLM 超时**：设置超时、有限重试和流式断开处理，返回可重试状态。
4. **SQLite 锁冲突**：缩短事务、设置合理 busy timeout；规模增长后迁移到共享数据库。
5. **检索结果为空**：返回澄清问题或知识不足，不直接调用通用模型编造农业建议。

## 九、可直接复述的选型取舍

> 我没有只使用向量检索，因为农业查询既有同义表达，也有必须精确命中的专业实体；也没有让图谱承担全部回答，因为图谱维护成本高、覆盖不可能完整。最终采用向量 + BM25 保召回，RRF 融合，Reranker 做精排，Neo4j 补充关系证据，模型只在证据约束下生成回答。这是精度、延迟、建设成本和可解释性的平衡。
