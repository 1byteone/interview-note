# 智颐养老护理系统（zznursing）— 项目速记卡

> **GitHub**: [zznursing](https://github.com/1byteone/zznursing)
> **框架**: Spring Boot 2.5.15 + MyBatis-Plus 3.5.2 + Spring Security 5.7.12 + JWT
> **模块**: 10 个（nursing-platform/admin/common/framework/system/oss/quartz/generator/miniapp/ui）
> **外部集成**: 百度千帆 AI、华为云 IoTDA、阿里云 OSS、微信小程序、Apache Qpid JMS

---

## 一、快速复习知识点速记（15 个核心知识点）

### 1. 健康评估 AI 引擎（PDF -> Redis -> 千帆 AI -> 结构化 JSON）
护理人员上传 PDF 体检报告 -> 阿里云 OSS 存储 -> PDFUtil 提取文本 -> Redis Hash（key=`healthReport`, field=身份证号）缓存 24h。提交评估时从 Redis 取文本，拼装 Prompt 调百度千帆 AI，返回 JSON 解析后落库。

### 2. Prompt 工程：6 个输出字段 + 强制 JSON
Prompt 要求 AI 以专业医生视角输出：总检日期、风险等级+健康指数、五级风险分布、异常数据（7 字段）、八大系统评分、总结。通过 `responseFormat` 设为 `json_object` 强制 JSON 输出，保证解析稳定性。

### 3. 健康指数 -> 护理等级映射
`getLevelNameByHealthScore()`: >=90 -> 四级护理, >=80 -> 三级, >=70 -> 二级, >=60 -> 一级, <60 -> 特级。同步设置 `suggestionForAdmission`（>=60 建议入住）。

### 4. 华为云 IoTDA 设备管理（产品同步 + 设备注册 + AMQP 消费）
产品列表全量同步到 Redis（`iot:all_product_list`），后续查询走 Redis，耗时从 3 分钟降到 10 秒。设备注册校验唯一性后生成随机 secret，先调华为云 API 注册再本地保存。

### 5. AMQP 消息消费（Apache Qpid JMS）
应用启动时 `AmqpClient` 实现 `ApplicationRunner`，建立 4 个 AMQP 连接（默认配置），通过 `MessageListener` + 线程池异步处理设备上报数据。`Session.AUTO_ACKNOWLEDGE` 模式自动确认消息。

### 6. 设备数据批量入库 + Redis Hash 最新缓存
`DeviceDataServiceImpl.batchInsertDeviceData()` 根据 `iotId` 查本地设备表，遍历属性 Map 批量插入 `device_data` 表，同时写入 Redis Hash（`iot:device_last_data`, field=iotId, value=JSON）。

### 7. 微信小程序登录（jscode2session + 手机号）
`WechatServiceImpl` 三步：`getOpenid(code)` 调微信 jscode2session 接口获 openid；`getPhone(detailCode)` 先调 `cgi-bin/token` 获 access_token，再调 `wxa/business/getuserphonenumber` 获手机号。`FamilyMemberServiceImpl.login()` 组装完整流程。

### 8. 小程序家属端登录流程
`FamilyMemberServiceImpl.login()`: openId 查库 -> 不存在则新建设置默认昵称（随机词组+手机号后四位）-> 获取手机号 -> saveOrUpdate -> 创建 JWT token（claims 含 userId + nickName）-> 返回前端。

### 9. Spring Security + JWT + RBAC 权限系统
基于 RuoYi-Vue 框架，管理端使用 Spring Security 过滤器链 + JWT 认证，小程序端使用独立的 `MemberInterceptor` 拦截器。RBAC 权限模型：用户 -> 角色 -> 菜单/权限，框架自动生成 CRUD 权限码。

### 10. ThreadLocal 用户上下文传递
`MemberInterceptor.preHandle()` 解析 header 中 JWT token -> 提取 userId -> 存入 `UserThreadLocal`（`ThreadLocal<Long>`）。Service 层通过 `UserThreadLocal.getUserId()` 获取当前用户。`afterCompletion()` 中 finally 块执行 `remove()` 防止内存泄漏。

### 11. 阿里云 OSS 文件存储（PDF 上传）
`AliyunOSSOperator` 封装阿里云 OSS SDK，PDF 体检报告上传后返回 URL，文本提取后存入 Redis 缓存。独立的 `zzyl-oss` 模块管理文件存储逻辑。

### 12. RuoYi-Vue v3.8.9 二次开发
基于 RuoYi-Vue 框架扩展，复用其 RBAC 权限、代码生成器、字典管理、操作日志、数据源动态切换等基础设施。改造点：新增 `zzyl-nursing-platform` 养老核心业务模块、独立小程序鉴权体系、外部 AI/IoT 集成。

### 13. 多模块架构（10 模块）
分层：`zzyl-nursing-platform`（养老核心业务）、`zzyl-admin`（Web 入口）、`zzyl-common`（公共工具+AI 调用）、`zzyl-framework`（安全框架+IoT 配置）、`zzyl-system`（系统管理）、`zzyl-oss`（文件存储）、`zzyl-quartz`（定时任务）、`zzyl-generator`（代码生成）、`zzyl-ui`（Vue 3 前端）、`zzyl-miniapp`（微信小程序）。

### 14. 百度千帆 AI 调用封装（OpenAI 兼容 SDK）
`AIModelInvoker.qianfanInvoker()` 使用 OpenAI 兼容 SDK，通过 `BaiduAIProperties`（`@ConfigurationProperties(prefix = "baidu.qianfan")`）配置 apiKey/baseUrl/model。`responseFormat` 设为 `json_object` 强制 JSON 输出。

### 15. 多端鉴权体系（管理后台 + 小程序双通道）
管理后台走 RuoYi 框架的 Spring Security 过滤器链（`JwtAuthenticationTokenFilter`），小程序端走独立的 `MemberInterceptor` 拦截器，共用 `TokenService` 创建/校验 JWT，但用户体系隔离（管理端用户表 vs 家属表）。

## 二、面试要点速记（8 个亮点）

### 项目一句话定位
"一个面向中型养老院的综合管理平台，覆盖健康评估、IoT 设备监控、护理工单等核心业务，支持管理后台与家属微信小程序双端访问，服务院内 500+ 设备、日均 2000+ 次家属端访问。"

### 核心技术亮点

**亮点 1：健康评估 AI 引擎**
- PDF 体检报告 -> 阿里云 OSS 存储 -> 文本提取 -> Redis 缓存（24h TTL）-> 百度千帆 AI 结构化分析 -> 自动生成健康指数、风险等级、护理等级建议
- 核心优化：PDF 文本缓存避免重复上传解析，AI 分析响应从 8s 降到 1s 以内，护理人员效率提升 30%
- Prompt 工程：6 个输出字段 + 强制 JSON 格式，保证解析稳定性

**亮点 2：IoT 设备实时监控**
- 华为云 IoTDA 产品/设备管理 + AMQP 消息订阅 + 线程池并发消费
- 产品列表全量同步到 Redis，查询耗时从 3 分钟降到 10 秒
- 设备数据批量入库 + Redis Hash 缓存最新数据，支持实时查询

**亮点 3：多端统一鉴权**
- 管理后台：Spring Security + JWT（RuoYi 框架标准方案）
- 微信小程序：jscode2session + 手机号授权 + 独立 JWT + 拦截器 + ThreadLocal
- 双端用户体系隔离，Token 统一管理，互不干扰

**亮点 4：RuoYi-Vue 二次开发实践**
- 复用成熟框架的基础设施（RBAC 权限、代码生成器、字典管理、操作日志），节省 3-4 周开发时间
- 在此基础上扩展养老业务核心模块，集成 AI/IoT/OSS 等外部服务

**亮点 5：AMQP 消息可靠消费**
- 应用启动自动建立 4 个 AMQP 连接，线程池异步处理，Session.AUTO_ACKNOWLEDGE
- 连接监听器（`JmsConnectionListener`）监控连接状态，失败自动重连

**亮点 6：ThreadLocal 内存泄漏防护**
- 拦截器 finally 块强制 `remove()`
- 代码规范要求：所有使用 ThreadLocal 的地方必须配套清理

**亮点 7：结构化 Prompt 工程**
- 角色设定 + 详细输出格式 + 示例数据 + 强制 JSON 格式
- 6 个输出字段覆盖健康评估全维度

**亮点 8：Redis 缓存策略**
- 健康报告文本：Hash 结构，身份证号做 field，24h TTL
- IoT 产品列表：String 类型，全量缓存
- IoT 设备最新数据：Hash 结构，iotId 做 field
- 多场景缓存，减少重复计算和外部调用的依赖

## 三、面试追问速记（20 个高频追问）

### Q1：为什么选百度千帆而不是其他大模型？
**要点**：项目预算有限，百度千帆提供免费额度，且与华为云 IoTDA 同为国产平台，客户（养老院）对数据合规有要求。如果未来需要更高精度，可通过 `AIModelInvoker` 切换模型（OpenAI 兼容 SDK，只需改配置）。

### Q2：健康评估 Prompt 怎么设计的？怎么保证输出稳定？
**要点**：角色设定（专业医生）-> 6 项输出要求 -> 示例数据格式 -> 强制 JSON 输出（`responseFormat: json_object`）。稳定性通过 `JSON.parseObject` 解析，解析失败时降级到规则引擎模式。

### Q3：AI 调用失败怎么降级？
**要点**：自动切换回规则引擎模式，基于体检指标与正常范围比对，超标的标注警示。虽然不如 AI 精准，但保证至少能用。同时记录失败日志触发告警。

### Q4：华为云 IoT 设备数据怎么保证不丢失？
**要点**：三层保障：1) 设备本地缓存最近一次数据，断网恢复后批量上报；2) 华为云 IoTDA 有离线消息缓存能力；3) AMQP 连接自动重连机制（`failover.reconnectDelay` 配置）。

### Q5：AMQP 消息消费失败怎么处理？
**要点**：当前使用 `Session.AUTO_ACKNOWLEDGE`，如果 `processMessage` 抛异常会丢失消息。改进方向：改为 `CLIENT_ACKNOWLEDGE`，处理成功后再手动 `message.acknowledge()`，失败时记录日志并投递到死信队列。

### Q6：ThreadLocal 内存泄漏问题怎么解决？
**要点**：ThreadLocal key 弱引用、value 强引用，线程池复用线程时 value 无法回收。三个措施：拦截器 finally 块 `remove()`、自定义 ThreadFactory 每次执行完清理、代码 Review 重点检查。

### Q7：JWT token 过期怎么处理？
**要点**：管理端使用 RuoYi 框架的 TokenService，token 过期后自动刷新（Redis 中续期）。小程序端 token 过期返回 401，前端引导用户重新登录授权。

### Q8：小程序登录流程具体怎么实现的？
**要点**：三步：1) `wx.login()` 获取 code -> 调 jscode2session 获 openid；2) `wx.getPhoneNumber()` 获取 detailCode -> 调微信接口获手机号；3) 后端根据 openid 查库，新用户自动创建（默认昵称 = 随机词组 + 手机号后四位），生成 JWT 返回。

### Q9：Redis 缓存和数据库一致性怎么保证？
**要点**：健康报告文本是只读缓存（上传后写入，24h 自动过期），不存在一致性问题。IoT 设备最新数据是最终一致性场景，写入时先写库再写缓存，允许短暂不一致。

### Q10：PDF 解析遇到加密文档怎么办？
**要点**：当前 `PDFUtil` 基于 PDFBox，不支持加密文档。改进方案：前端上传时校验 PDF 是否加密，加密文档提示用户先解密；后端捕获异常后返回友好提示。

### Q11：多端登录（管理端+小程序）session 怎么管理？
**要点**：两套独立用户体系。管理端：用户表（sys_user）+ Spring Security 上下文。小程序：家属表（family_member）+ ThreadLocal（`UserThreadLocal`）。JWT token 通过 `TokenService` 统一管理，但用户隔离，互不串号。

### Q12：物联网设备数据量大的时候怎么处理？
**要点**：当前通过 `batchInsertDeviceData` 批量插入，`saveBatch(list)` 一次提交多条。如果数据量进一步增大，可考虑：1) 增加 AMQP 连接数（当前 4 个）；2) 引入消息队列缓冲；3) 时序数据库存储设备数据。

### Q13：为什么用 RuoYi-Vue 二次开发？做了什么改造？
**要点**：RuoYi-Vue 提供成熟的后台管理基础设施，节省 3-4 周开发时间。改造点：新增 `zzyl-nursing-platform` 模块承载养老业务、新增小程序独立鉴权体系、集成外部 AI/IoT/OSS 服务、扩展全局异常处理。

### Q14：健康指数和护理等级映射规则怎么定的？
**要点**：`getLevelNameByHealthScore()`: >=90 四级, >=80 三级, >=70 二级, >=60 一级, <60 特级。>=60 同时建议入住。该规则基于行业经验，结合 AI 分析的健康指数自动判定，减少人工评估的主观性。

### Q15：怎么防止重复提交评估？
**要点**：RuoYi 框架提供 `@RepeatSubmit` 注解，基于 Redis SETNX 实现，30 秒内同一请求不可重复提交。可在 Controller 层添加该注解防止重复提交。

### Q16：IoT 设备离线怎么检测？
**要点**：当前没有主动离线检测机制。改进方向：定时任务扫描 `iot:device_last_data` 中最近更新时间超过阈值的设备，标记为离线状态并触发告警。

### Q17：消息队列积压怎么处理？
**要点**：监控 AMQP 队列积压情况。当前通过线程池异步消费，如果消费速度跟不上，可考虑：增加消费者连接数、优化批量插入性能、引入 RocketMQ 作为缓冲层。

### Q18：权限系统怎么设计的（RBAC 具体实现）？
**要点**：基于 RuoYi-Vue 标准 RBAC：用户（sys_user）-> 角色（sys_role）-> 菜单/权限（sys_menu）。`@PreAuthorize` 注解在 Controller 方法上标注权限标识，Spring Security 在请求时校验。代码生成器自动生成 CRUD 权限码。

### Q19：阿里云 OSS 怎么集成到项目中的？
**要点**：独立 `zzyl-oss` 模块，封装 `AliyunOSSOperator` 工具类，配置 OSS endpoint/accessKey/bucketName。PDF 上传时返回文件 URL 存入数据库，文本提取后缓存到 Redis。支持文件类型校验和大小限制。

### Q20：项目中用到了哪些设计模式？
**要点**：1) 模板方法：`AbstractQuartzJob` 定时任务基类；2) 策略模式：数据源动态切换（`DynamicDataSourceContextHolder`）；3) 外观模式：`AIModelInvoker` 封装 AI 调用细节；4) 单例模式：Spring Bean 默认单例；5) 代理模式：Spring AOP 日志切面（`LogAspect`）。
