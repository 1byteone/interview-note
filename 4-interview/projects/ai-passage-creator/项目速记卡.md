## 一、快速复习知识点速记（15 个核心知识点）

1. **StateGraph 工作流引擎**：`ArticleAgentOrchestrator` 将创作拆为 5 个节点（Title → Outline → Content → Image → Merge），分 3 个阶段执行，串行 + 并行编排，新增模式只需配节点和边。
2. **17 个状态键**：`taskId` / `topic` / `style` / `methodology` / `userDescription` / `userId` / `mainTitle` / `subTitle` / `titleOptions` / `outline` / `content` / `contentWithPlaceholders` / `imageRequirements` / `images` / `fullContent` / `enabledImageMethods` / `ragReferences`，全部使用 `ReplaceStrategy` 在节点间传递。
3. **4 个异步线程池隔离**：article(5-10, 队列 100) / skill(5-15, 队列 200) / card(2-4, 队列 50) / rag(2-4, 队列 100)，互不干扰、按业务隔离。
4. **SSE 流式输出**：`SseEmitterManager`（30 分钟超时、3s 重连、心跳保活、identity-guarded 移除），首字延迟 200ms 内，接口吞吐量提升 50%。
5. **ParallelImageGenerator**：实现 `NodeAction`，按 `imageSource`（PEXELS / NANO_BANANA）分组，用 `CompletableFuture.runAsync` 并行生成——不同 source 并行、同 source 串行，逐张推送 `IMAGE_COMPLETE` 事件。
6. **GuestRateLimiter 限流**：内存滑动窗口（`ConcurrentHashMap<String, Deque<Long>>`），游客默认 5 次/分钟，按 guestId 加 synchronized，用户登录则不限。
7. **Spring AI Alibaba ChatClient + ChatModel**：统一封装大模型调用，配合 StructuredOutputConverter 将不同模型输出转成标准格式。
8. **ContentMergerAgent 内容合并**：纯静态函数 `mergeImagesIntoContent()`，用 `placeholderId` 定位正文占位符替换为 `![description](url)`，可被重写服务复用。
9. **RAG 引用集成**：`ragReferences` 状态键 + `ragExecutor` 线程池做向量索引，正文生成时携带参考溯源。
10. **RabbitMQ 状态同步**：异步任务 FAILED 进延迟消息重试队列，最多 3 次，超限进死信队列触发告警，用户可查任务状态。
11. **Redis 缓存**：生成结果缓存，同主题/同风格复用，减少重复调用大模型的开销。
12. **CallerRunsPolicy 拒绝处理**：除 card 外三个池在满时让调用方线程执行任务，自然降速不丢任务；card 用 AbortPolicy 防 Playwright OOM。
13. **@EnableAsync + ThreadPoolTaskExecutor**：`AsyncConfig` 三个 `@Async("xxxExecutor")` 阶段方法，`setWaitForTasksToCompleteOnShutdown(true)`。
14. **优雅停机**：`setAwaitTerminationSeconds`（article/skill/card 60s，rag 30s），停机时等待在途任务完成。
15. **跨 ClassLoader 对象拷贝**：DevTools 热重启时 StateGraph 返回对象类型不匹配，用 Jackson `ObjectMapper` 深拷贝（`copyValue` / `copyList` / `copyOutlineResult`）解决。

## 二、面试要点速记

### 项目一句话定位

> 一个基于 Spring AI Alibaba StateGraph 的多智能体图文创作平台，将「标题→大纲→正文→配图→合并」拆解为可编排的工作流，异步线程池 + SSE 流式输出解决长文生成的等待与体验问题。

### 核心技术亮点（面试必讲）

| 亮点 | 要点 |
|------|------|
| **StateGraph 串行 + 并行编排** | 5 节点 3 阶段，正文串行链路与多图配图并行生成同图并存；数据通过 17 个状态键解耦传递，节点单一职责、可插拔扩展 |
| **异步线程池隔离** | 4 个独立线程池按业务隔离（文章/技能/卡片/向量索引），参数与拒绝策略按任务特性差异化设计 |
| **SSE 流式输出体验** | 逐 Token 打字机推送 + 事件协议（14 种消息类型）+ 心跳 + 断线重连，首字延迟 200ms 内 |
| **限流与防滥用** | 内存滑动窗口 GuestRateLimiter，游客 5 次/分钟，登录用户走额度体系 |
| **稳定性保障** | 拒绝策略分级（CallerRuns 兜底 vs Abort 防 OOM）+ 优雅停机 + 失败重试（MQ 延迟消息 3 次）+ 图源降级 99%+ |

**量化成果**：403 个 Java 源文件 / 33 个 Agent 文件 / 500 字约 15s、2000 字约 45s / 首字延迟 <200ms / 吞吐量提升 50% / 图源降级成功率 99%+。

## 三、面试追问速记（18 个高频追问 + 答案要点）

1. **为什么选择 StateGraph 而不是直接串行调用？**
   直接串行调用是硬编码流程，新增/调整环节要改调用链；StateGraph 把流程拆成可编排的节点 + 边，正文节点后紧跟并行配图节点，天然支持 DAG 并行，扩展新模式（如加审核节点）只需配置新节点和边。

2. **17 个状态键是怎么管理的？**
   定义为 `KEY_XXX` 常量集中管理，全部使用 `ReplaceStrategy`；设计原则是"节点只读自己需要的键、只写自己负责的键"，任务身份（taskId/userId）贯穿全程，避免大对象重复塞入状态。

3. **异步线程池参数怎么设置的？为什么？**
   article 5-10 队列 100：文章生成本身是 IO 密集（等大模型），核心数小、队列中等；skill 5-15 队列 200：技能任务更轻更频繁；card 2-4 队列 50：Playwright 浏览器进程吃内存，必须压住并发；rag 2-4：向量索引不阻塞主流程。核心原则：按任务的 CPU/内存/IO 特性分别调参，互不抢资源。

4. **线程池满了怎么办（CallerRunsPolicy）？**
   CallerRunsPolicy 让提交任务的调用方线程同步执行，相当于生产者变消费者、自动降速，任务不丢但接口变慢，是一种背压手段；cardExecutor 特意用 AbortPolicy——卡片渲染并发过高会让 Playwright 崩（OOM），宁可拒绝报错也不能拖垮整个进程。

5. **如何处理 SSE 连接断开？**
   `SseEmitter` 的 onCompletion / onTimeout / onError 回调中用 `emitterMap.remove(taskId, emitter)` 做 identity-guarded 移除（防重连时误删新 emitter）；心跳注释 `comment("heartbeat")` 探活，客户端 3s 重连，SSE 基于 HTTP 天然支持断线重连。

6. **图片生成失败怎么降级？**
   按 `imageSource` 分组并行，某一路失败不影响其他路；单张失败时走向本地/备选图源兜底，成功率 99%+；全部失败则正文保留占位符，合并阶段优雅处理而不是中断整个流程。

7. **多智能体之间如何通信？**
   通过 StateGraph 的 State（17 个状态键）传递结构化数据，节点只依赖输入契约；流式回调不走 State，用 ThreadLocal 的 `StreamHandlerContext` 传 `Consumer<String>`，避免把不可序列化的函数塞进状态。

8. **长文本生成超时怎么处理？**
   任务状态机 PENDING → RUNNING → SUCCESS/FAILED；FAILED 进 RabbitMQ 延迟消息重试队列，最多重试 3 次，超限进死信队列告警；用户端经任务 ID 查询状态，SSE 侧 30 分钟超时 + 心跳保持连接。

9. **如何保证内容质量和一致性？**
   结构化输出（StructuredOutputConverter + schema 校验，格式不对自动重试）统一格式；每个 Agent 单一职责确保内容连贯；RAG 引用做事实溯源；合并阶段做整体一致性收口。

10. **并发请求怎么隔离？**
    线程池隔离 + SSE 任务 ID 隔离（SseEmitterManager 按 taskId 管理）+ AgentRequestRegistry 按 `u:{userId}` / `g:{guestId}` 做订阅越权校验，用户数据经 userId 租户隔离（含 RAG 检索）。

11. **速率限制怎么实现的？**
    `GuestRateLimiter` 内存滑动窗口：`ConcurrentHashMap<String, Deque<Long>>` 记录每个 guestId 的时间戳队列，`tryAcquire()` 时先清理过期记录再判断窗口内次数，默认 5 次/分钟，per-guest 同步；登录用户不走此限流。

12. **如何扩展新的生成模式？**
    无需改引擎代码——在 `AgentConfig` 开关（`orchestratorEnabled`）基础上新增节点（实现 `NodeAction`）和边，在 StateGraph 中组合；配图方式通过 `enabledImageMethods` 白名单配置，加新图源只需实现新 `ImageSource` 分组。

13. **StateGraph 和 LangGraph 的异同？**
    理念同源——节点 + 边 + 状态传递 + 条件分支；区别在生态语言：LangGraph 是 Python 生态、和 LangChain 深度绑定，StateGraph 是 Java/Spring AI 内建编排组件，能直接复用 Spring Bean、事务和现有基础设施，适合纯 Java 团队。

14. **Java 21 虚拟线程能用吗？为什么没用？**
    能。虚拟线程适合海量 IO 型任务，但这里是"受控的少量并发 + 需要限流/背压 + 需要控制浏览器进程类重型资源并发"（Playwright 不能按请求开线程），Spring AI 调用也含非阻塞流式处理；传统池化模型 + 拒绝策略更可控，且发布时团队对 Loom 生态兼容性（如线程本地、同步锁）仍有顾虑——可作为演进方向回答。

15. **如何做内容缓存？**
    Redis 缓存生成结果，命中后直接返流，减少重复调用大模型；`METHODOLOGY`（方法论模板）等配置类数据热点缓存；注意按 userId 隔离缓存键，避免越权读到他人内容。

16. **流式输出和分块返回的区别？**
    分块是"按业务的自然段落/阶段"一次推一大块（如 AGENT1_COMPLETE 到 AGENT5_COMPLETE 阶段事件）；流式是模型逐 Token/逐 delta 推送（text_delta），配合打字机效果。两者在事件协议中共存：结构进度用阶段事件，正文内容用增量流。

17. **用户取消请求怎么处理？**
    前端断开 SSE（onError/onCompletion 回调触发）；后端据 `CancellationToken`/任务状态标记取消，异步任务在线程池内优雅退出（配合 waitForTasksToCompleteOnShutdown）；未消费的 SSE emitter 由 timeout + 清理机制回收，防内存泄漏。

18. **RAG 引用怎么集成到生成流程？**
    ContentGeneratorAgent 阶段：正文生成前经 ragExecutor 线程池做向量检索，检索结果写入 `ragReferences` 状态键，正文 Prompt 注入参考片段并要求溯源；命中时 SSE 推送 `RAG_REFERENCE_FOUND` / `agent.rag_reference` 事件，前端展示引用来源，全链路可通过 userId 隔离租户数据。
