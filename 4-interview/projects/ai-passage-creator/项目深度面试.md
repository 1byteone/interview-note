## 一、项目全景概述

### 1.1 项目定位

灵犀写作是一个基于 Spring Boot 3.5 + Java 21 + Spring AI Alibaba 的 AI 智能图文创作平台。我独立设计了基于 StateGraph 的多智能体工作流引擎，将长文生成拆解为标题生成→大纲构建→正文撰写→配图选择→内容合并的串行/并行编排流程，解决传统 AI 生成长文时等待时间长、内容结构松散的问题。

### 1.2 项目规模

- **Java 源文件**: 403 个
- **Agent 相关文件**: 33 个
- **异步线程池**: 4 个（article/skill/card/rag）
- **Spring Boot 版本**: 3.5.13
- **Java 版本**: 21

### 1.3 技术架构

```
前端 (用户请求) → Controller → ArticleAgentOrchestrator (StateGraph)
  ├── Phase 1: TitleGeneratorAgent (标题生成)
  ├── Phase 2: OutlineGeneratorAgent (大纲构建)
  ├── Phase 3: ContentGeneratorAgent (正文撰写, 含 RAG 参考)
  ├── Phase 4: ImageAnalyzerAgent + ParallelImageGenerator (配图)
  └── Phase 5: ContentMergerAgent (内容合并)
       ↓
  异步线程池 (articleExecutor 5-10)
       ↓
  SSE 流式输出 (StreamingResponse)
       ↓
  Redis 缓存 + RabbitMQ 状态同步
```

## 二、核心模块深度剖析

### 2.1 StateGraph 工作流引擎

**代码位置**: `agent/ArticleAgentOrchestrator.java`

```java
@Service
public class ArticleAgentOrchestrator {

    // 5 个 Agent 节点
    @Resource private TitleGeneratorAgent titleGeneratorAgent;
    @Resource private OutlineGeneratorAgent outlineGeneratorAgent;
    @Resource private ContentGeneratorAgent contentGeneratorAgent;
    @Resource private ImageAnalyzerAgent imageAnalyzerAgent;
    @Resource private ParallelImageGenerator parallelImageGenerator;
    @Resource private ContentMergerAgent contentMergerAgent;

    // 阶段 1: 生成标题方案
    public void executePhase1_GenerateTitles(ArticleState state, Consumer<String> streamHandler) {
        Map<String, Object> inputs = new HashMap<>();
        inputs.put(KEY_TASK_ID, state.getTaskId());
        inputs.put(KEY_TOPIC, state.getTopic());
        inputs.put(KEY_STYLE, state.getStyle());
        // 构建并执行 StateGraph
        StateGraph graph = buildPhase1Graph();
        CompiledGraph compiledGraph = graph.compile();
        Optional<OverAllState> result = compiledGraph.invoke(inputs);
    }
}
```

**状态键常量**（17 个）：`taskId`、`topic`、`style`、`methodology`、`mainTitle`、`subTitle`、`titleOptions`、`outline`、`content`、`contentWithPlaceholders`、`imageRequirements`、`images`、`fullContent`、`enabledImageMethods`、`ragReferences` 等。

**设计理念**：StateGraph 将文章生成拆解为独立的节点，每个节点只负责一个任务。节点之间通过 State 传递数据，支持串行执行（标题→大纲→正文）和并行执行（同时生成多张配图）。新增一种生成模式只需配置新的节点和边，不需要改引擎代码。

### 2.2 异步任务体系

**代码位置**: `config/AsyncConfig.java`

```java
@Configuration
@EnableAsync
public class AsyncConfig {

    @Bean(name = "articleExecutor")
    public Executor articleExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(5);
        executor.setMaxPoolSize(10);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("article-async-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.setWaitForTasksToCompleteOnShutdown(true);
        executor.setAwaitTerminationSeconds(60);
        return executor;
    }

    @Bean(name = "skillExecutor")  // 5-15, queue 200
    @Bean(name = "cardExecutor")   // 2-4, queue 50, AbortPolicy
    @Bean(name = "ragExecutor")    // 2-4, queue 100, CallerRunsPolicy
}
```

**4 个线程池隔离设计**：

| 线程池 | 核心 | 最大 | 队列 | 拒绝策略 | 用途 |
|--------|------|------|------|---------|------|
| articleExecutor | 5 | 10 | 100 | CallerRuns | 文章生成任务 |
| skillExecutor | 5 | 15 | 200 | CallerRuns | Skill 引擎任务 |
| cardExecutor | 2 | 4 | 50 | AbortPolicy | 卡片渲染（Playwright 防 OOM） |
| ragExecutor | 2 | 4 | 100 | CallerRuns | 向量索引（不阻塞主流程） |

### 2.3 SSE 流式输出

整合 Spring AI Alibaba 的 StreamingResponse，实现 AI 生成内容的逐 Token 推送。前端展示打字机效果，首字延迟控制在 200ms 以内。异步任务体系使接口吞吐量提升 50%。

## 三、技术难点与解决方案

### 难点 1：StateGraph 的跨 ClassLoader 对象拷贝

**问题**: Spring Boot DevTools 热重启时，RestartClassLoader 和 app 类加载器不同，导致 StateGraph 中传递的对象类型不匹配。

**方案**: 使用 `ObjectMapper` 做深拷贝，避开 ClassLoader 差异。

### 难点 2：多个异步线程池的任务隔离

**问题**: 文章生成、卡片渲染、向量索引等任务混用同一个线程池，可能导致重要任务被阻塞。

**方案**: 4 个独立线程池，每个有独立的配置和拒绝策略。cardExecutor 用 AbortPolicy（直接拒绝，防止 Playwright 进程 OOM），其他用 CallerRunsPolicy（调用方线程执行，自然降速）。

### 难点 3：AI 生成结果的格式控制

**问题**: 不同大模型返回的格式不一致，有的纯文本，有的 JSON，有的带 Markdown。

**方案**: Prompt 模板引擎 + StructuredOutputConverter，统一将各种模型的输出转换为标准格式。底层用 Pydantic schema 校验，格式不对自动重试。

## 四、高频面试题

**Q1: StateGraph 和 Spring StateMachine 的区别？**

Spring StateMachine 适合业务流程审批这种有限状态机场景，状态转移是预定义的。我的 StateGraph 更像是一个 DAG 执行引擎，节点可以并行执行，状态可以在节点间自由传递，适合 AI 工作流这种数据驱动的场景。

**Q2: 为什么用 SSE 而不是 WebSocket？**

SSE 更简单——单向的（服务端推），基于 HTTP，天然支持断线重连和负载均衡。WebSocket 是双向的，对于"AI 生成文本推送到前端"这个场景，双向通信是多余的。Spring Boot 3 对 SSE 的支持也很简洁，一个 `StreamingResponse` 就够了。

**Q3: 异步任务失败怎么处理？**

任务状态有四种：PENDING → RUNNING → SUCCESS / FAILED。FAILED 的任务进入重试队列（RocketMQ 延迟消息），最多重试 3 次。超过次数进入死信队列，触发告警。用户端可以通过任务 ID 查询状态。

**Q4: 4 个线程池的拒绝策略为什么不同？**

cardExecutor 的 AbortPolicy 是最严格的——卡片渲染需要 Playwright 浏览器进程，并发过高会导致 OOM，宁可拒绝也不能让系统崩溃。其他三个线程池的 CallerRunsPolicy 更温和，调用方线程执行相当于自然降速，不会丢任务。
