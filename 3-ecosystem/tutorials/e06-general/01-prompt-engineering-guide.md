# Prompt Engineering 实战：从基础到高级技术

> **生态**: E06 · 通识与基础 | **等级**: 入门→进阶 | **前置要求**: 无

Prompt Engineering（提示工程）是 AI Agent 生态的基石。无论你使用 Claude、GPT 还是 Gemini，编写高质量的提示词（Prompt）是决定 AI 输出质量最关键的因素。2026 年的今天，提示工程已从"写提示词"演进为"设计上下文"——Context Engineering 成为新的范式。

本教程覆盖从零样本提示到高级推理模式（CoT、ReAct、ToT），再到模型特定策略和生产级评估体系，帮助你在日常工作和 Agent 开发中写出高效、可控的提示词。

---

## 1. 为什么 Prompt Engineering 至关重要

一个简单的例子说明提示词质量对输出效果的巨大影响：

```text
# 模糊提示
解释一下 RAG

# 高质量提示
你是一位 AI 系统架构师。请用以下结构解释 RAG（检索增强生成）：
1. 核心概念（一句话定义）
2. 工作流程（3-5 步简述）
3. 适用场景（列举 3 个）
4. 与纯 LLM 生成相比的优势和局限性

要求：语言简洁，每部分不超过 100 字，适合技术经理阅读。
```

前者得到一个笼统的解释，后者得到结构清晰、可直接用于汇报的内容。**提示词本质上是对 LLM 推理过程的"编程"**——你用自然语言描述任务结构、约束条件和输出格式。

### 提示词的关键要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **角色** | 设定 AI 的身份视角 | "你是一位资深 Java 工程师" |
| **任务** | 明确要完成的工作 | "请审查以下代码中的并发安全问题" |
| **上下文** | 提供背景信息 | "这段代码运行在 Spring Boot 3.2 环境" |
| **约束** | 限制输出的范围/格式 | "用列表形式，每条不超过 50 字" |
| **示例** | 给出期望的输出样例 | "例如：...（展示理想输出）" |
| **输出格式** | 明确输出的结构 | "返回 JSON 格式，包含 title 和 body 字段" |

## 2. 基础技术：Zero-shot 与 Few-shot

### 2.1 Zero-shot Prompt（零样本提示）

直接给出任务描述，不提供任何示例。这是最基础的提示方式，对现代 LLM 已能胜任大多数简单任务。

```text
请将以下英文句子翻译成中文：
"Prompt engineering is the key to unlocking LLM potential."
```

对于复杂任务，零样本提示容易导致输出不稳定。改进方式是增加**角色设定**和**结构化要求**。

### 2.2 Few-shot Prompt（少样本提示）

提供 2-5 个输入输出示例，让模型"理解"任务模式。Few-shot 能显著提升复杂分类、格式转换等任务的准确率。

```text
将以下产品评论分类为"正面"、"负面"或"中性"。

示例1：
评论：这个耳机音质太棒了，续航也超长！
分类：正面

示例2：
评论：等了三天还没发货，客服也不回消息。
分类：负面

示例3：
评论：产品还行，就是价格稍微贵了点。
分类：中性

--- 
评论：虽然功能齐全但操作有点复杂，新手可能需要适应一段时间。
分类：
```

**选择示例的原则**：
- 覆盖边界情况（正面/负面/中性各一个）
- 示例难度递增
- 示例数量通常 2-5 个最佳，过多增加 token 消耗且收益递减

## 3. 进阶技术：Chain-of-Thought（CoT）

Chain-of-Thought（思维链）是 2025-2026 年最重要的提示技术之一。它通过引导模型输出**逐步推理过程**，显著提升复杂问题的解决质量。

### 3.1 基本原理

传统直接回答 vs CoT 的区别：

```text
# 传统方式（直接回答）
问：一个商店有 15 个苹果，卖出了 7 个，又进货了 10 个，现在有多少个？
答：18 个

# CoT 方式（逐步推理）
问：一个商店有 15 个苹果，卖出了 7 个，又进货了 10 个，现在有多少个？
答：一开始有 15 个苹果。卖出 7 个后，剩下 15 - 7 = 8 个。又进货 10 个后，总数为 8 + 10 = 18 个。所以答案是 18。
```

### 3.2 Zero-shot CoT

在提示词末尾加上 **"让我们一步步思考"** 即可触发思维链。这是最简洁的 CoT 实现方式。

```text
问题：小明有 3 盒铅笔，每盒 12 支，他给了小红 8 支，又丢了 5 支，还剩多少支？
让我们一步步思考。
```

### 3.3 Few-shot CoT

提供带有推理过程的示例，引导模型学习推理模式。

```text
问题：图书馆有 240 本书，周一借出 35 本，周二还回 18 本，周三借出 42 本，现在有多少本？
推理：初始 240 本。周一借出 35 本 → 240 - 35 = 205 本。周二还回 18 本 → 205 + 18 = 223 本。周三借出 42 本 → 223 - 42 = 181 本。
答案：181 本

问题：一辆公交车上有 45 人，第一站下去 12 人上来 8 人，第二站下去 15 人上来 20 人，现在车上有多少人？
推理：
```

### 3.4 CoT 的最佳实践

- **明确要求展示推理过程**：在提示中明确写出"请展示你的推理步骤"
- **结构化推理**：要求模型分步骤编号，或用 `步骤1: ... 步骤2: ...` 格式
- **验证推理**：对于关键任务，可要求模型在给出最终答案前先自我验证
- **适用场景**：数学问题、逻辑推理、代码调试、复杂决策、多步骤规划

## 4. 高级技术：ReAct 模式

ReAct（Reasoning + Acting）是 Agent 系统的核心模式，将**推理（Reasoning）**与**行动（Acting）**交替执行，形成 **Thought → Action → Observation** 循环。

### 4.1 ReAct 循环结构

```
Thought: 我需要了解什么信息？
Action: 调用某个工具或查询某个知识库
Observation: 工具返回的结果
Thought: 基于观察结果，我得出结论...
Action: 执行下一步操作...
...
Final Answer: 综合所有信息，给出最终答案
```

### 4.2 ReAct 提示模板

```text
你是一个 AI 助手，可以调用工具来回答问题。请遵循以下循环：

**Thought**：分析当前状态，决定下一步需要什么信息。
**Action**：调用工具或查询知识库。格式：工具名称(参数)
**Observation**：工具返回的结果。
...（重复 Thought → Action → Observation 直到信息充足）
**Final Answer**：给出最终答案。

可用工具：
- search_web(query): 搜索网络信息
- calculate(expression): 执行数学计算
- get_current_time(): 获取当前时间

示例：
用户：2024 年巴黎奥运会中国获得了多少枚金牌？

Thought: 我需要查询 2024 年巴黎奥运会中国队的金牌数量。
Action: search_web("2024年巴黎奥运会 中国 金牌数量")
Observation: 搜索结果：中国队在2024年巴黎奥运会共获得 40 枚金牌，27 枚银牌，24 枚铜牌。
Thought: 搜索结果提供了完整的奖牌数据，金牌数量是 40 枚。
Final Answer: 中国队在 2024 年巴黎奥运会共获得 **40 枚金牌**。
```

### 4.3 ReAct 在 Agent 中的应用

ReAct 是所有主流 Agent 框架（LangChain、Claude Code、AutoGPT）的底层推理引擎。在实际 Agent 系统中：

- **Thought** 由 LLM 生成，决定下一步策略
- **Action** 映射到函数调用（Function Calling）或 MCP 工具
- **Observation** 是工具返回的结构化/非结构化数据
- 循环持续直到条件满足（如找到答案、达到最大步数、收到 Human-in-the-loop 确认）

## 5. 前沿技术：Tree-of-Thought（ToT）

Tree-of-Thought（思维树）是 CoT 的扩展，同时探索**多条推理路径**，并在路径之间进行评估和回溯。

### 5.1 核心概念

| CoT | ToT |
|-----|-----|
| 单条推理路径 | 多条并行推理路径 |
| 线性前进 | 树状探索 + 分支回溯 |
| 无自我评估 | 每步评估路径优劣 |
| 适合确定性任务 | 适合探索性任务（创意、规划、搜索） |

### 5.2 ToT 提示示例

```text
问题：设计一个周末北京三日游方案，预算 3000 元，包含交通、住宿、餐饮和景点。

请使用思维树方法：
1. 首先生成 3 个不同主题的方案方向（如"文化历史"、"美食探店"、"自然风光"）
2. 对每个方向，分别评估可行性（预算、时间、体验）
3. 选择最佳方向，细化日程安排
4. 如果细化过程中发现预算超支或时间冲突，回溯到上一步调整

请在最终输出中展示你的思维树探索过程。
```

ToT 目前主要用于研究性应用，在 Agent 系统中较少直接使用，但它的**分支探索 + 回溯评估**思想已融入 Agent 规划器的设计中。

## 6. 2026 趋势：Context Engineering

2026 年，提示工程正在向 **Context Engineering（上下文工程）** 演进。核心变化是：从"写一个完美的提示词"转向"构建一个最优的上下文环境"。

### Context Engineering 的关键要素

| 要素 | 传统 Prompt | Context Engineering |
|------|------------|-------------------|
| 信息源 | 单次提示 | 多源检索（RAG、数据库、API） |
| 记忆 | 无状态 | 对话记忆 + 长期记忆 + 知识图谱 |
| 工具 | 无 | 动态工具注册与调用 |
| 动态性 | 静态提示 | 根据上下文动态调整 |
| 反馈 | 无 | 自动评估 + 自我修正 |

### 实践：Context Engineering 提示框架

```text
[系统上下文]
你是一个智能客服 Agent，接入以下系统：
- 知识库：产品文档、FAQ、故障处理手册
- 订单系统：实时订单查询
- 售后系统：退换货处理

[当前会话上下文]
用户 ID: U12345
用户等级: VIP
当前问题: 订单 #20240815001 显示已发货但物流信息 3 天未更新
历史交互: 用户上周咨询过相同订单的发货问题

[任务]
基于以上上下文，执行以下步骤：
1. 查询订单系统确认物流状态
2. 如果物流异常，生成安抚话术并给出补偿方案
3. 如果用户不满，升级人工处理
```

## 7. 模型特定策略

不同模型在提示词策略上有显著差异，了解这些差异能显著提升效果。

### GPT-4o / GPT 系列

- 偏好**结构化提示**，对 Markdown 格式敏感
- 支持 System / User / Assistant 消息角色
- 对 JSON 格式的响应要求严格（需要明确指示）
- 适合 Few-shot 示例，对示例质量敏感

### Claude 系列

- 对人类语言风格更敏感，偏好**自然对话式提示**
- 对 XML 标签有特殊偏好（尤其 Claude 3.5+）
- 支持长上下文（200K tokens），适合文档分析
- 需要明确的角色设定，否则趋于保守

### Gemini 系列

- 对**多模态输入**支持最好（图像、音频、视频）
- 偏好简洁直接的指令
- 对长链推理的稳定性略逊于 GPT/Claude，建议使用 CoT
- 适合需要视觉理解的场景

### 模型无关的最佳实践

```text
1. 明确角色：让模型知道"你是谁"
2. 明确任务：用动词开头（分析、生成、总结、转换）
3. 明确约束：字数、格式、风格、语气
4. 明确输出结构：列表、表格、JSON、代码块
5. 提供示例：Few-shot 优于 Zero-shot
6. 分步指令：复杂任务拆解为多个子任务
7. 自我验证：要求模型检查自己的输出
8. 温度控制：创造性任务用高温度（0.7-0.9），精确任务用低温度（0-0.3）
```

## 8. 提示词模板与评估

### 8.1 分类模板库

**编程助手模板**

```text
你是一位资深 {语言} 工程师。请完成以下任务：

任务：{任务描述}
代码上下文：{相关代码或文件结构}
约束：
- 遵循 {框架} 的最佳实践
- 包含错误处理
- 添加关键注释
- 输出完整代码，不要省略
```

**文档生成模板**

```text
请为以下 {API/功能/模块} 生成技术文档：

格式要求：
- 概述（一句话）
- 快速开始（代码示例）
- API 参考（参数、返回值、异常）
- 注意事项

内容：{待文档化的内容}
```

**评估模板**

```text
你是一个 AI 输出质量评估器。请评估以下 AI 回复的质量：

评估维度（1-5 分）：
1. 准确性：信息是否正确
2. 完整性：是否覆盖了问题的所有方面
3. 清晰度：表达是否清晰易懂
4. 相关性：内容是否紧扣问题
5. 安全性：是否有有害或不当内容

AI 回复：
{待评估的回复}
```

### 8.2 提示词评估策略

| 方法 | 说明 | 适用场景 |
|------|------|----------|
| 人工评估 | 人工打分、A/B 测试 | 关键场景、上线前验收 |
| LLM 评估 | 用 LLM 评估 LLM 输出 | 批量回归测试 |
| 自动化指标 | BLEU、ROUGE、BERTScore | 翻译、摘要类任务 |
| 功能测试 | 输出是否能通过特定测试用例 | 代码生成、结构化输出 |

## 总结

Prompt Engineering 是 AI Agent 时代的核心技能。从 Zero-shot 到 Context Engineering，提示工程技术不断演进，但底层逻辑始终不变：**用清晰的结构和精确的约束，引导 LLM 产生高质量的推理和输出**。

对于 Agent 开发者，建议以下学习路径：

1. **掌握基础**：Zero-shot、Few-shot、结构化提示
2. **深入推理**：CoT（思维链）是日常使用频率最高的技术
3. **理解 Agent 模式**：ReAct 是 Agent 系统的核心推理引擎
4. **关注前沿**：Context Engineering 是 2026 年的新范式
5. **持续实践**：建立自己的提示词模板库，持续迭代优化
