🔗 实体关系说明
User 1 ──→ N MonthlyPlan 一个用户（员工）按月制定多个月计划
MonthlyPlan 1 ──→ N DailyPlan 一个月计划拆解为 15-22 个日计划
DailyPlan 1 ──→ N Result 一个日计划可分阶段提交多次成果（长周期任务）
Result N ──→ 1 MonthlyPlan 成果同时关联月计划（支持跨日计划的产出）
Result 1 ──→ N Evidence 一个成果携带多个证据附件（PR/报告/截图/文档）
Result 1 ──→ 1 SelfEvaluation 每个成果附带一份员工自评
ApprovalRecord 多态关联 MonthlyPlan 通过 target_type + target_id 关联计划审批或成果验收
OperationLog 多态关联 任意实体 记录所有业务操作的完整审计轨迹
设计要点：ApprovalRecord 采用多态关联（target_type + target_id），统一处理计划审批和成果验收两种审批场景，避免为每种审批单独建表。OperationLog 同样采用多态关联，记录所有业务操作的 who / when / what / before / after，为后续审计、绩效统计和问题追责提供完整的数据基础。is_retroactive 字段标记"事后补录"的计划，用于统计补录率——这个数字本身就是一个管理质量指标。
