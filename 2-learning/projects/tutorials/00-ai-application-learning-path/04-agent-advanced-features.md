# Agent 高级特性：流式、并发与中间件

> 来源：`第3章 智能体的高级特性.docx`。本文以行为语义为主，API 名称需与锁定版本核对。

## 流式事件

建议对外统一事件：`status`、`delta`、`tool`、`sources`、`done`、`error`。事件应包含 request/thread 标识和可重放的序号。不要把底层框架事件直接暴露为长期稳定协议。

## 同步、异步与批处理

- `invoke`：单次同步调用；
- `ainvoke`：异步单次调用；
- 批处理：适合独立请求，必须限制并发；
- 流式：适合降低首字响应时间，但不能改变最终一致性。

对工具和模型调用分别设置超时，取消请求时应停止后续工具调用并释放连接。

## 动态 Prompt 与中间件

动态 Prompt 只能补充经过权限过滤的用户上下文，不能让用户覆盖系统安全规则。中间件适合统一做日志脱敏、重试、限流、工具审计和输出校验；副作用逻辑不要在不幂等的重试钩子中重复执行。

## 多模态

多模态输入必须检查模型能力、文件大小、媒体类型、病毒扫描和隐私；不要假设文本模型可以直接处理图片或 PDF。

## 并行与条件分支

并行分支要明确失败策略：全失败、部分成功还是降级。条件路由应使用枚举状态，不使用模型自由生成的字符串作为安全决策。

## 练习

为“玉米黄斑”设计 `retrieval` 和 `weather` 两个工具：限制最大步数为 4，工具超时 3 秒，检索为空时进入拒答分支，并为每个事件添加序号。
