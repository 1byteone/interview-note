# AI、LLM、Prompt 与 Agent 基础

> 来源：`几个重要概念.docx`、`第1章 概述.docx`。本章只整理概念和工程边界，不绑定某个模型厂商。

## 学习目标

- 区分 LLM、Token、Context Window 和 Prompt；
- 说明普通模型调用与 Agent 的差异；
- 理解 Tool Calling 和 Memory 的边界；
- 能画出农业问答 Agent 的基本执行链路。

## 1. LLM 不是数据库

LLM 根据输入上下文预测后续 Token。它擅长语言理解、改写、总结和生成，但不天然知道实时库存、最新政策或私有文档。需要事实依据时，应通过数据库、检索系统或受控工具补充，并对结果做权限和业务校验。

## 2. Token 与 Context

Token 是模型 tokenizer 切分出的文本片段，TokenId 是当前 tokenizer 词表中的数字编号。同一段中文在不同模型中的 Token 数量和编号可能不同，因此不能跨模型复用 TokenId，也不能用字符数精确估计上下文消耗。

Context Window 是一次请求中模型可见的上下文容量，它不是长期记忆。上下文过长时应采用摘要、截断或检索，而不是无限追加历史消息。

## 3. Prompt 分层

- **System Prompt**：角色、规则、输出约束和安全边界；
- **User Prompt**：当前用户任务；
- **检索上下文**：外部系统返回的事实证据；
- **工具结果**：受控工具的执行结果。

System Prompt 不是权限系统。涉及数据访问、写操作和高风险农业建议时，必须在服务端实施鉴权、白名单、参数校验和审计。

## 4. Agent 闭环

教学上的简化表达是：

```text
Agent = LLM + Tools + State
```

典型闭环：

```text
感知问题 → 规划步骤 → 选择工具 → 执行工具 → 观察结果
    ↑                                      ↓
    └──────────── 继续、拒答或完成 ────────┘
```

与普通一次性 LLM 调用相比，Agent 多了工具选择、状态管理和终止条件。生产系统必须限制最大步数、总耗时、工具权限和资源消耗。

## 5. 农业问答示例

```text
用户：玉米叶片出现黄斑，应该如何处理？
  → Domain Guard 判断是否属于农业问题
  → Query Router 提取作物、症状和生育期
  → 检索农业知识库
  → 检查证据来源、时间和置信度
  → 证据充分：生成带引用的建议
  → 证据不足：说明资料不足并请求补充信息
```

农药剂量、施用期限和政策解释属于高风险内容，不应只依赖模型自由生成。

## 6. Tool Calling 与 Memory

工具是受控能力的接口，例如检索、天气查询或日期计算。工具定义应包含参数 Schema，并在服务端再次校验参数；模型生成的工具参数不能直接信任。

- **短期记忆**：当前线程中的消息和状态，受上下文容量限制；
- **持久化状态**：保存线程、任务和检查点，便于恢复；
- **长期用户记忆**：必须有来源、权限、删除和过期策略；
- **知识库**：存放可检索事实，不等同于用户记忆。

## 面试要点

1. 为什么 RAG 不能简单等同于“把文档拼到 Prompt”？
2. 为什么 TokenId 不能跨模型复用？
3. Agent 循环如何防止无限执行？
4. 为什么 System Prompt 不能替代权限控制？
5. 短期记忆、检查点、长期记忆和知识库有什么区别？
