# 01 · 整体系统架构

> 本文从全局视角描述 AI 智能商城的系统架构，包括服务划分、技术选型理由和部署拓扑，是理解整个贯穿项目的入口。

## 一、系统架构分层

## 三、技术选型理由

### 3.1 为什么 Java + Python 双语言？

| 维度 | Java (Spring Cloud) | Python (FastAPI) |
|------|--------------------|-----------------|
| **业务复杂度** | 适合复杂业务逻辑、事务管理、企业级中间件 | 适合 AI 推理、数据管道、快速原型 |
| **生态成熟度** | Spring Cloud 生态是微服务工业标准 | LangChain/LangGraph 是 AI 应用事实标准 |
| **性能** | 多线程模型成熟，适合 IO 密集型业务 | 异步模型高效，适合 AI 推理调度 |
| **团队分工** | 后端工程师维护业务服务 | AI 工程师维护智能服务 |

**结论：** 双语言不是"多此一举"，而是"各司其职"。Java 处理复杂业务逻辑和事务一致性，Python 处理 AI 推理和向量化。两者通过 HTTP API 通信，解耦独立。

### 3.2 为什么用 Spring Cloud Alibaba 而不是 Spring Cloud Netflix？

| 对比项 | Spring Cloud Alibaba | Spring Cloud Netflix |
|--------|--------------------|--------------------|
| 注册中心 | Nacos（AP+CP 双模式） | Eureka（AP，已停更） |
| 配置中心 | Nacos（配置管理+长轮询刷新） | Config（已停更） |
| 限流熔断 | Sentinel（实时监控+控制台） | Hystrix（已停更） |
| 分布式事务 | Seata（AT/TCC/Saga） | 无 |

**结论：** Netflix 组件大部分已进入维护期，Alibaba 组件在中国市场广泛使用且持续更新，更适合国内电商场景。

### 3.3 为什么用 Redis 做向量数据库？

| 对比项 | Redis Stack | Milvus | Pinecone |
|--------|------------|--------|----------|
| 学习成本 | 低（已有 Redis 基础设施） | 高（独立系统） | 低（SaaS） |
| 部署成本 | 低（单实例/集群） | 高（集群运维） | 高（付费） |
| 查询延迟 | ~1ms | ~10ms | ~10ms |
| 适用场景 | 演示/中规模 | 大规模生产 | 云端 |

**结论：** 当前数据量（<100 万 SKU）下 Redis 足够，且复用现有基础设施。未来数据量增长可平滑迁移到 Milvus，因为 LangChain 的 VectorStore 抽象屏蔽了底层差异。

## 五、服务间通信方式

| 通信模式 | 工具 | 场景 |
|---------|------|------|
| **同步 HTTP** | OpenFeign + LoadBalancer | 服务间短暂查询（用户信息、商品信息） |
| **异步消息** | RocketMQ | 订单创建、支付回调、库存扣减 |
| **数据同步** | Canal + RocketMQ | MySQL → ES 商品同步 |
| **AI 服务调用** | 网关路由 + HTTP | Java 服务 → Python AI 服务 |
| **配置推送** | Nacos 长轮询 | 配置动态刷新 |
| **服务发现** | Nacos | 服务注册与健康检查 |
