## 场景一：从客户下单到收款的全链路设计

### 场景描述

客户下了一笔 500 万的订单（1000 台智能手表），要求 45 天内交货。请设计从接单到收款的完整三域协同方案。

### 需求分析

```
1. ERP：创建销售订单 → 库存检查 → MRP → 缺料分析
2. ERP→OA：采购审批（原材料 300 万）
3. ERP→MES：生产工单（1000 台手表）
4. MES：排产 → 领料 → 生产 → 报工 → 质检 → 完工
5. MES→ERP：完工入库 + 成本归集
6. ERP：发货 → 开票 → 收款
7. OA：全程审批（采购、工单、发货、开票）
```

### 三域协同方案

| 阶段 | 域 | 操作 | 事件 |
|------|-----|------|------|
| 1 | ERP | 创建 SO，库存检查：成品 200，缺 800 | - |
| 2 | ERP | MRP 展开：表壳自制，屏幕外购 | erp.mrp.completed |
| 3 | OA | 采购审批：屏幕 800 个 × 200 元 = 16 万 | oa.purchase.approved |
| 4 | ERP | 创建 PO → 供应商送货 → 入库 | erp.po.received |
| 5 | OA | 工单审批 | oa.workorder.approved |
| 6 | MES | 创建工单 → 排产 → 领料 → 生产 | mes.wo.in_progress |
| 7 | MES | 45 天完工 996 台（不良 4 台） | mes.wo.completed |
| 8 | ERP | 成品入库 → 成本归集 | erp.stock.manufactured |
| 9 | ERP | 发货 → 开票 → 收款 | erp.invoice.paid |

### 面试官考察点

- O2C + P2P + MRP + MES 的完整链路
- 三域事件驱动协同
- 异常处理（不良品、缺料）

## 场景二：三域架构下的"紧急插单"处理

### 场景描述

生产进行中，大客户突然下一个紧急订单：100 台手表，3 天内交货。当前产线已排满 5 天的工单。

### 三域协同方案

```
1. ERP：创建紧急 SO（优先级=URGENT）
   ↓
2. ERP 重排计划：
   · 识别可延迟的工单（交期弹性大的）
   · 计算物料齐套（紧急订单的原料是否到位）
   ↓
3. ERP→MES：暂停可延迟工单，插入紧急工单
   · MQ: erp.workorder.urgent_insert
   ↓
4. MES：调整排产
   · 紧急工单分配到空闲设备
   · 优先领料
   · 优先报工
   ↓
5. MES→ERP：紧急工单完工回报
   ↓
6. ERP：紧急发货 → 通知客户
   ↓
7. OA：通知相关方交期调整
```

### 面试官考察点

- 跨域协同的实时性
- 排产调整的可行性
- 通知机制（OA 通知）

## 场景三：供应商质量问题导致的三域联动

### 场景描述

某供应商的原料批次 RM-20260801-003 被投诉有质量问题。需要追溯所有使用了该批次原料的成品，锁定受影响批次，通知客户，处理退货。

### 三域协同方案

```
1. MES：正向追溯
   · RM-20260801-003 → 哪些成品批次用了它
   → 成品批次 FG-20260815-001, FG-20260818-002
   ↓
2. MES：锁定受影响批次（status=LOCKED）
   ↓
3. MES→ERP：通知成品库存冻结
   ↓
4. ERP：查询哪些客户收到了受影响批次的成品
   ↓
5. OA：创建质量异常审批
   → 质量经理 → 采购经理 → 总经理
   ↓
6. 审批通过：决策（召回/让步接收/报废）
   ↓
7. ERP：执行退货/报废处理
   ↓
8. OA：通知客户
   ↓
9. MES：记录处置结果（追溯闭环）
```

### 面试官考察点

- 正向追溯的完整链路
- 三域协同处理质量问题
- 处置决策的审批流程

## 场景四：月末结账的三域协同

### 场景描述

设计月末结账流程，要求三域数据一致、财务报表准确。

### 三域协同方案

```
月末结账流程（T日）：

T-1 日：准备阶段
├── ERP：截止当月业务（过账日期 = T-1）
├── MES：汇总当月完工数据
├── OA：汇总当月审批数据
└── 三域：停止新业务录入

T 日：结账阶段
├── MES→ERP：发送当月完工数据（Outbox）
│   · 工单完工数量、不良数、工时
├── ERP：成本归集
│   · 材料成本：汇总领料记录
│   · 人工成本：报工工时 × 工位费率
│   · 制造费用：按分摊规则
│   → 生成成本结转凭证
├── ERP：损益结转
│   · 汇总收入、成本、费用
│   · 计算本月利润
│   → 生成结转凭证
├── ERP：生成报表
│   · 资产负债表
│   · 利润表
│   · 现金流量表
├── 三域：对账
│   · MES 工单 vs ERP 生产订单
│   · OA 审批单 vs ERP 单据
│   · 差异生成对账报告
└── ERP：关账（锁定当月凭证）
```

### 面试官考察点

- 月末结账的业务流程
- 三域数据归集
- 对账机制

## 场景五：三域架构的容灾设计

### 场景描述

设计三域架构的容灾方案，保证单点故障不影响整体业务。

### 三域协同方案

| 故障场景 | 影响范围 | 容灾方案 |
|---------|---------|---------|
| MES 挂了 | 生产执行停摆 | ERP 工单状态冻结，不继续下发；MES 恢复后自动续做 |
| ERP 挂了 | 销售/采购/财务停摆 | OA 审批继续（缓存审批状态）；ERP 恢复后批量处理 |
| OA 挂了 | 审批停摆 | 紧急审批走线下流程；OA 恢复后补录 |
| MQ 挂了 | 三域集成中断 | Outbox 暂存消息；MQ 恢复后自动投递 |
| MySQL 挂了 | 全面影响 | 主从切换（自动 failover） |
| Redis 挂了 | 权限/缓存失效 | 降级到数据库查询（性能下降但可用） |

### 面试官考察点

- 各域的容灾优先级
- MQ 的可靠性设计
- 降级策略
