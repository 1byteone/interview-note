# 速记版：30 个高频考点

> 面试前 10 分钟快速翻阅，覆盖 RocketMQ 最核心知识点。

---

## 一、基础概念（8 题）

### 1. RocketMQ 核心组件有哪些？

| 组件 | 作用 |
|------|------|
| **NameServer** | 路由注册中心，轻量级，无状态，可集群部署 |
| **Broker** | 消息存储与转发，主从架构 |
| **Producer** | 消息生产者，支持同步/异步/单向发送 |
| **Consumer** | 消息消费者，支持集群/广播消费 |
| **Topic** | 消息主题，一类消息的逻辑分类 |
| **Queue** | 消息队列，Topic 下的物理分区，并发度由 Queue 数决定 |

### 2. 消息发送三种方式？

| 方式 | 可靠性 | 场景 |
|------|--------|------|
| 同步发送 | 高 | 关键业务（订单、支付） |
| 异步发送 | 中 | 对延迟敏感，回调确认 |
| 单向发送 | 低 | 日志、监控 |

### 3. 集群消费 vs 广播消费？

- **集群消费**：一条消息只被消费组内一个实例消费（负载均衡，默认）
- **广播消费**：每条消息被所有实例消费（数据同步）

### 4. 如何保证消息有序？

- **全局顺序**：只建 1 个 Queue（吞吐极低，不推荐）
- **分区顺序**：按业务 key（如订单号）hash 到固定 Queue，同一 Queue 内串行消费

### 5. 消息过滤方式？

- **Tag 过滤**：Topic 下的二级分类，简单等值匹配，性能高
- **SQL 过滤**：消息属性 SQL92 表达式，支持复杂条件

### 6. 延迟消息机制？

18 个固定延迟等级（1s/5s/10s/30s/1m...2h），实现原理：延迟 Topic + 定时扫描转投。

### 7. 消费模式中的 Queue 分配？

- 一个 Queue 最多被一个消费线程消费
- 一个消费者可消费多个 Queue
- 消费并发度 = min(线程数, Queue 数)

### 8. 消息的存储结构？

CommitLog（顺序写文件） + ConsumeQueue（索引文件） + IndexFile（索引）

## 二、事务消息（5 题）

### 9. 事务消息流程？

① 发送半消息（不可见）→ ② 执行本地事务 → ③ 提交/回滚 → ④ 超时未提交触发回查

### 10. 半消息是什么？

发送到 Broker 但暂不可见的消息，存在 `RMQ_SYS_TRANS_HALF_TOPIC` 中。

### 11. 事务回查机制？

Broker 发现半消息长时间未提交，主动回调 Producer 的 `checkLocalTransaction()` 获取状态。

### 12. 事务消息 vs 本地消息表？

| 维度 | 事务消息 | 本地消息表 |
|------|----------|------------|
| 一致性 | 强（Broker 参与） | 最终一致 |
| 实现复杂度 | 高（监听器+回查） | 低（定时任务扫表） |
| 对业务侵入 | 低 | 中（需要消息表） |

### 13. 事务消息 vs Seata TCC？

- 事务消息：最终一致，适合下单+扣库存等异步场景
- Seata TCC：近似强一致，适合账户扣款等实时场景

## 三、可靠性（5 题）

### 14. 消息丢失的三个环节？

| 环节 | 保障 |
|------|------|
| 生产端 | 同步发送 + 重试 + 本地消息表 |
| Broker 端 | 同步刷盘 + 主从同步 |
| 消费端 | 手动提交 offset + 重试机制 |

### 15. 同步刷盘 vs 异步刷盘？

| 方式 | 可靠性 | 性能 |
|------|--------|------|
| 同步刷盘 | 写入磁盘才返回，不丢消息 | 低 |
| 异步刷盘 | 写入 PageCache 即返回 | 高 |

### 16. 消费重试机制？

失败后重试 16 次，间隔递增：10s → 30s → 1min → ... → 2h。超过后进死信队列。

### 17. 死信队列是什么？

- 超过最大重试次数的消息进入死信队列
- Topic 格式：`%DLQ%consumerGroupName`
- 需要人工介入排查

### 18. 如何保证消息不重复消费？

**消费端幂等**：唯一键表、Redis 锁、状态机、乐观锁。RocketMQ 只保证至少一次投递。

## 四、高可用与性能（6 题）

### 19. Dledger 是什么？

基于 Raft 协议的多副本机制，实现 Broker 自动故障转移。

### 20. Dledger 选举过程？

Leader 宕机 → Follower 心跳超时 → 发起 Raft 选举 → 多数派投票 → 新 Leader 产生。

### 21. 消息积压怎么排查？

- 控制台查看 Diff Total（积压量）
- 检查消费端是否异常（DB 慢查询、接口超时）
- 临时扩容消费实例

### 22. 消息积压怎么处理？

- 临时扩容消费端（增加实例 + 增加 Queue）
- 跳过不可重试的业务异常消息
- 死信队列人工介入

### 23. 消费端性能调优参数？

| 参数 | 说明 |
|------|------|
| `consumeThreadMin` | 最小消费线程数 |
| `consumeThreadMax` | 最大消费线程数 |
| `pullBatchSize` | 单次拉取消息数 |
| `consumeMessageBatchMaxSize` | 批量消费最大条数 |

### 24. 批量发送注意事项？

- 同一 Topic、同一批次
- 总大小 ≤ 4MB
- 建议先压缩再发送

## 五、对比与选型（3 题）

### 25. RocketMQ vs Kafka 核心差异？

| 维度 | RocketMQ | Kafka |
|------|----------|-------|
| 吞吐 | 10万+ TPS | 百万级 TPS |
| 事务消息 | 支持 | 不支持 |
| 延迟消息 | 支持 | 不支持 |
| 消息轨迹 | 原生支持 | 需插件 |
| 单机部署 | 轻量 | 需 ZooKeeper/KRaft |

### 26. RocketMQ vs RabbitMQ 核心差异？

| 维度 | RocketMQ | RabbitMQ |
|------|----------|----------|
| 吞吐 | 10万+ TPS | 万级 TPS |
| 路由模式 | Topic/Queue | Exchange/Binding |
| 消息堆积 | 亿级 | 百万级 |
| 延迟 | 毫秒 | 微秒 |

### 27. 什么场景选 RocketMQ？

- Java 微服务业务解耦
- 需要事务消息、延迟消息
- 需要消息轨迹和死信队列
- 秒杀削峰

## 六、实战经验（3 题）

### 28. 秒杀削峰方案？

Redis 预扣库存 → RocketMQ 消息排队 → 后端限流消费 → DB 乐观锁写入。

### 29. 幂等方案实现？

推荐唯一键表：`INSERT INTO idempotent_record(msg_id) VALUES(?);` 重复插入抛 `DuplicateKeyException` 跳过。

### 30. 消息链路追踪怎么实现？

消息头携带 `traceId`，消费端 MDC 写入，日志中透传，数据库建消息追踪表。
