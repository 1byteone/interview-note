## 一、平台定位（Q1-Q3）

| # | 问题 | 速记答案 |
|---|------|---------|
| 1 | LangSmith 是什么？ | LangChain 官方 AI 应用可观测 + 评测平台，覆盖开发调试（Tracing）→ 评测（Evaluation）→ 生产监控（Monitoring）全生命周期 |
| 2 | 铁三角关系？ | LangChain **构建**（造）、LangGraph **编排**（跑）、LangSmith **验证**（看 + 量）；LangSmith 追踪前两者执行并用数据集评测质量 |
| 3 | 接入要配什么？ | 两个环境变量：`LANGCHAIN_TRACING_V2=true` + `LANGCHAIN_API_KEY`，零侵入自动上报；纯函数用 `traceable` |

## 二、Tracing 概念（Q4-Q5）

| # | 问题 | 速记答案 |
|---|------|---------|
| 4 | Trace / Run / Thread？ | Thread（会话）→ Trace（单次执行树）→ Run（执行步骤）；Run 记录输入输出 / token / 延迟 / 错误 |
| 5 | 如何自定义追踪？ | `traceable` 装饰任意函数；手动用 `client.trace`；跨服务用 trace_id 传递聚合 |

## 三、评测体系（Q6-Q9）

| # | 问题 | 速记答案 |
|---|------|---------|
| 6 | Dataset / Experiment？ | Dataset=考卷（输入+期望+标签）；Experiment=考生成绩单（目标函数在考卷上跑完 + 评估器打分）；同一考卷可对比多个考生 |
| 7 | 评估器三态？ | 代码规则（确定性，格式/实体/契约）、LLM-as-Judge（语义，相关性/忠实度）、人工标注（复杂轨迹兜底） |
| 8 | 自定义评估器签名？ | `(run: Run, example: Example|None) -> {"key","score","comment"}`；轨迹级可断言"是否调用了某工具" |
| 9 | LLM-as-Judge 校准？ | 评分锚点 + few-shot 对齐 + 人类反馈回灌 + 固定裁判模型防漂移；三层互补（规则快 + 裁判语义 + 人工兜底） |

## 四、Prompt 管理（Q10）

| # | 问题 | 速记答案 |
|---|------|---------|
| 10 | Prompt Hub 价值？ | 版本化 + 回滚 + 团队协作 + 热更新（不重启切 tag）+ 绑评测；发布纪律：先评测 → 切 prod → 监控回归 → 秒回滚 |

## 五、反馈闭环与生产监控（Q11-Q13）

| # | 问题 | 速记答案 |
|---|------|---------|
| 11 | Feedback？ | 给 run 挂结构化反馈（点赞/踩/评分）；负反馈是最宝贵的评测素材 |
| 12 | Annotation Queue？ | 人工评审工作流：规则筛选 trace 入队 → 专家打标 → 沉淀 Dataset → 评测改进 |
| 13 | Automation？ | 条件 + 动作规则引擎：负反馈/异常 → 入队 / Webhook / 入 Dataset / 告警；把失败自动变"待评审 + 数据 + 告警" |
| 13b | 生产监控看什么？ | 质量（在线评估/反馈/错误样本率）、健康（错误率/p95 延迟/工具失败率）、成本（每 run 价格/token 趋势）三层 |

## 六、选型对比与综合（Q14-Q15）

| # | 问题 | 速记答案 |
|---|------|---------|
| 14 | LangSmith vs Langfuse？ | 主轴：生态绑定（LangSmith 零侵入）vs 开放自托管（Langfuse 开源）；LangChain 栈 + 接受协同 → LangSmith；多框架/数据主权 → Langfuse |
| 15 | 用 LangSmith 定位线上错误回答？ | 五步：收 trace → 回看输入 → 三处归因（检索空召回/生成注入/校验放行）→ 样本入集复现修复 → 监控回归 |
