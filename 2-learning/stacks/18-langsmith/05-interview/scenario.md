## 场景一：线上回答"答非所问"，如何用 LangSmith 定位并修复？

### 问题描述

商城 RAG 问答上线后，运营反馈：用户问"这款手机支持 5G 吗"，系统回答却是"这款手机性价比很高，拍照不错，推荐购买"。没有报错，但回答完全没答到点上。

### 参考思路

**Step 1 · 收 trace（数据先行）**
- 找到该反馈对应的 Thread → 打开瀑布视图
- 三处观察：检索节点命中什么？模型输入是什么？输出是什么？

**Step 2 · 三处归因**

| 怀疑点 | 怎么看 | 典型根因 |
|--------|--------|---------|
| 检索没召回正确答案 | Retriever run 的 hits：命中片段是否含"5G/网络制式"字段 | 商品参数没进向量库 / chunk 切分丢了规格 / embedding 对"5G"这类短查询不敏感 |
| 检索召回了但模型没用 | ChatModel 输入：上下文是否被截断 / prompt 是否要求"只讲推荐不讲参数" | system prompt 重推荐轻参数 / 上下文窗口截断 |
| 检索为空 → 模型只能硬编 | Retriever hits 为空 | top-k 太小 / 查询改写失败 / 分库错误 |

**Step 3 · 复现与修复**
- 把该样本加入 Dataset（标签 `参数类`）
- 本地复现 → 修复（补参数入库 / 调 top-k / 加"参数类问题必须查规格字段"的 prompt 约束 / 空召回走兜底"我查一下参数"）
- 跑 Experiment 对比修复前后忠实度 + 相关性分数

**Step 4 · 回归闭环**
- 配 Automation：`faithfulness < 0.6` 自动入队复核 → 确认入评测集 → 同类问题回归门禁拦截

**面试加分点**：强调"**先看 trace 再改代码**"，以及"修复必须回测 + 进评测集防复发"——这是生产排障的正确姿势。

## 场景二：评测集还是空的，怎么开始第一次评测？

### 问题描述

团队第一次引入 LangSmith，没有任何评测集。Leader 说"先建个评测集测起来"，但大家不知道该放什么样本。

### 参考思路

**Step 1 · 从"高频 + 高风险 + 已知坏例"起步（不追求大）**
- 高频：线上 Top 查询（真实流量里占比最高的 10-20 条）
- 高风险：答错了代价高的（农技方案 / 价格参数 / 医疗建议类）
- 已知坏例：把过去人工发现的错误回答先收进来
- 起步 50-100 条即可，覆盖主要分支 + 边界

**Step 2 · 用"能自动跑"的评估器先动起来**
- 代码规则优先（JSON 合法 / 必含实体 / 长度）——零成本立刻有分
- 再挂 RAG 忠实度 / 相关性官方评估器
- LLM 裁判最后补（需要写锚点，成本最高）

**Step 3 · 跑 baseline（第一次就是基准线）**
- 当前生产 prompt + 当前模型跑一次，记下分数 = baseline
- 以后每次改动都对比 baseline，**"这次改动是变好还是变坏"从此有数据**

**Step 4 · 让评测集"活"起来**
- 配 Automation 把生产负反馈自动沉淀入集
- 每 1-2 周合并一次新坏例，更新样本版本

**面试加分点**：强调"**第一次评测不是为了高分，是为了建立 baseline**"——评测工程第一步是校准标尺，不是冲刺分数。

## 场景三：生产环境没有外网，能用 LangSmith 吗？

### 问题描述

某政企项目，AI 应用跑在内网，数据不能出网，但团队想要可观测和评测能力。

### 参考思路

**三条路径对比：**

| 方案 | 做法 | 适用 |
|------|------|------|
| 私有化部署 LangSmith | 内网部署 LangSmith 私有版（Docker） | 预算充足 + 深度依赖 LangChain 生态 |
| 开源替代 Langfuse | 自托管 Langfuse（开源自部署） | 数据主权 + 开源免费，接受弱评测/弱部署集成 |
| 自建轻量方案 | 日志 + trace_id + 简单评测脚本（LLM 裁判调内网模型） | 起步阶段 / 需求简单 |

**关键决策维度**：数据主权要求（必私有的底线）→ 预算（私有化费用 vs 自建人力）→ 功能需求（只要追踪？还要评测 / Prompt 管理？）。

**推荐务实路径**：内网先用 **Langfuse 自托管**（追踪 + 基础评测免费），评测集导出可迁移；若深度使用 LangChain 生态且预算到位再评估 LangSmith 私有化。

**面试加分点**：体现"**先想清需求再选工具**"——把可观测需求拆成追踪 / 评测 / 管理三层，再按数据主权与预算匹配方案，而不是无脑推 SaaS。
