# MES 面试场景题（5 个综合实战场景）

> 每个场景覆盖多个知识点，考察综合设计能力。

## 场景一：智能手表生产线数字化改造

### 场景描述

某智能手表制造企业，3 条产线，200+ 设备，日产能 5000 台。目前用 Excel 管理工单和排产，经常出现：
- 排产冲突（两条线排了同一个工单）
- 物料领错（A 工单领了 B 工单的料）
- 追溯困难（客户投诉时查不到原料来源）
- 成本不准（不知道每个工单实际花了多少）

老板要求：上 MES 系统，3 个月内上线核心模块。

### 需求分析

| 问题 | 根因 | MES 解决方案 |
|------|------|------------|
| 排产冲突 | 无系统化排产 | 工单 + 排产模块，设备互斥约束 |
| 物料领错 | 无领料校验 | 领料单绑定工单，扫码领料 |
| 追溯困难 | 无追溯记录 | 批次 + SN 追溯模块 |
| 成本不准 | 无报工数据 | 报工模块，记录实际工时和消耗 |

### 技术方案

```
Phase 1（1 个月）：核心模块
├── 主数据：物料、BOM、工艺、工位
├── 工单管理：创建、下达、领料、完工
└── 基础报表

Phase 2（1 个月）：执行模块
├── 排产：工单分配到产线/工位
├── 报工：操作员扫码报工
└── 质检：IPQC + FQC

Phase 3（1 个月）：高级模块
├── 追溯：批次 + SN 正反向追溯
├── 设备管理：OEE 统计
└── 数字大屏：ECharts 可视化
```

### 面试官考察点

- 能否从业务问题推导出技术方案
- 能否做合理的分期规划（MVP 思维）
- 能否识别关键风险（物料齐套、设备兼容）

## 场景二：批次召回全流程

### 场景描述

某食品企业收到供应商通知：原料批次 RM-20260801-003（面粉）存在质量问题，需要召回所有使用了该批次面粉的成品。

### 需求分析

| 步骤 | 操作 | 系统支持 |
|------|------|---------|
| 1. 正向追溯 | 查出 RM-20260801-003 被用在哪些成品 | 正向追溯查询 |
| 2. 锁定批次 | 将受影响的成品批次标记为"锁定" | 批次状态管理 |
| 3. 通知客户 | 通知购买了受影响成品的客户 | ERP 集成 |
| 4. 处置决策 | 召回 / 让步接收 / 报废 | 质量处置流程 |
| 5. 记录归档 | 追溯记录和处置记录归档 | 审计日志 |

### 技术方案

```sql
-- Step 1: 正向追溯
WITH RECURSIVE forward_trace AS (
    SELECT output_batch_id, work_order_id, consumed_qty, 1 AS depth
    FROM mes_batch_relation
    WHERE input_batch_id = (
        SELECT id FROM mes_trace_batch WHERE batch_no = 'RM-20260801-003'
    )
    UNION ALL
    SELECT r.output_batch_id, r.work_order_id, r.consumed_qty, t.depth + 1
    FROM mes_batch_relation r
    JOIN forward_trace t ON r.input_batch_id = t.output_batch_id
    WHERE t.depth < 10
)
SELECT
    b.batch_no AS 成品批次,
    b.material_id AS 成品物料,
    wo.order_no AS 工单号,
    t.consumed_qty AS 消耗数量
FROM forward_trace t
JOIN mes_trace_batch b ON t.output_batch_id = b.id
JOIN mes_work_order wo ON t.work_order_id = wo.id;

-- Step 2: 锁定受影响批次
UPDATE mes_trace_batch
SET status = 'LOCKED'
WHERE id IN (SELECT output_batch_id FROM forward_trace);

-- Step 3: 通知 ERP（Outbox 模式）
INSERT INTO mes_outbox (message_type, payload, status)
VALUES ('batch.recall', '{"batch":"RM-20260801-003","affected_batches":[...]}', 'PENDING');
```

### 面试官考察点

- 能否完成端到端的追溯流程设计
- 能否考虑数据一致性和审计要求
- 能否设计合理的处置决策流程

## 场景三：MES 与 ERP 集成方案设计

### 场景描述

公司用 ERPNext 管理销售、采购、库存、财务，现在要上 MES 管理生产执行。需要设计 MES 与 ERPNext 的集成方案。

### 需求分析

| 集成场景 | 方向 | 实时性要求 | 方案 |
|---------|------|-----------|------|
| 生产订单下发 | ERP → MES | 实时 | REST API |
| BOM 同步 | ERP → MES | 准实时 | MQ + REST |
| 完工回报 | MES → ERP | 实时 | Outbox + MQ |
| 库存同步 | 双向 | 准实时 | MQ |
| 成本归集 | MES → ERP | 批量 | 定时任务 |

### 技术方案

```
ERPNext                          MES
  │                               │
  │──生产订单创建──→ REST API ──→│ 创建工单
  │                               │
  │←──工单状态回报── Outbox + MQ ──│
  │                               │
  │──BOM 变更通知──→ MQ ───────→│ 更新 BOM
  │                               │
  │←──完工入库回报── Outbox + MQ ──│
  │                               │
  │←──OEE 日报───── 定时任务 ─────│
  │                               │
  │──库存同步──────→ MQ ←────────│
  │                               │
  └─────────── 对账任务（每日日终）──┘
```

### 面试官考察点

- 能否设计异构系统集成方案
- 能否选择合适的集成模式（实时/异步/批量）
- 能否设计数据一致性保障机制

## 场景四：智能排产系统设计

### 场景描述

3 条产线，每条线 5-8 台设备，每天要排 50-100 个工单。排产员每天花 2 小时手动排产，紧急插单时经常手忙脚乱。

### 需求分析

| 约束条件 | 说明 |
|---------|------|
| 设备互斥 | 每台设备同一时间只能加工一个工单 |
| 工序顺序 | 工单必须按工序 1→2→3 执行 |
| 交期优先 | 紧急工单优先排产 |
| 物料齐套 | 原料到位才能开工 |
| 换型时间 | 同产品连续排产减少换型 |
| 人员排班 | 操作员有排班，非 24h 可用 |

### 技术方案

```
用户输入（自然语言）
    ↓
LLM Agent 理解意图
    ↓
查询上下文（RAG + 数据库）
    ↓
生成约束模型参数
    ↓
OR-Tools 求解器求解
    ↓
生成排产方案 + 甘特图
    ↓
人工确认 / 自然语言调整
```

### 面试官考察点

- 能否建模复杂的排产约束
- 能否选择合适的求解方案（启发式 vs 精确求解）
- 能否设计人机交互流程

## 场景五：质量异常根因分析

### 场景描述

某电子厂的 FQC 检测发现，最近 3 天焊接工序的不良率从 2% 飙升到 8%。质量工程师需要快速定位根因。

### 需求分析

需要关联分析的多维数据：

| 数据维度 | 来源 | 分析点 |
|---------|------|--------|
| 质检数据 | MES 质检模块 | 不良类型分布、时间趋势 |
| 设备日志 | SCADA/PLC | 温度、压力、振动异常 |
| 操作记录 | MES 报工模块 | 换班、操作员变更 |
| 物料批次 | MES 追溯模块 | 原料批次变更、供应商变更 |
| 环境数据 | 环境传感器 | 温湿度变化 |

### 技术方案

```
1. 数据收集
   · 查询近 3 天焊接工序的所有质检记录
   · 查询焊接设备的运行日志（温度、压力）
   · 查询操作员换班记录
   · 查询原料批次信息

2. LLM 分析
   · 将多维数据结构化后喂给 LLM
   · Prompt: "分析以下焊接不良率飙升的数据，定位根因"
   · LLM 结合 RAG 知识库（历史案例、设备手册）

3. 输出根因报告
   · 根因：设备 EQ-003 温度波动（14:00-15:00 波动 ±5°C）
   · 证据：温度日志 + 不良时间分布 + 设备维护记录
   · 建议：检查温控器，更换加热元件
   · 影响范围：WO-20260831-001 ~ WO-20260831-005

4. 处置跟踪
   · 创建设备维修工单
   · 跟踪维修进度
   · 维修完成后重新验证
```

### 面试官考察点

- 能否设计多维数据关联分析方案
- 能否合理使用 LLM（知道它的能力边界）
- 能否形成闭环的处置流程
