## 二、BOM（物料清单）

### 2.1 什么是 BOM

BOM（Bill of Materials）是产品的"配方"——它定义了一个成品由哪些子件、各需要多少数量组成。

```
成品：智能手表（SKU: SW-001）
├── 表壳（半成品）×1
│   ├── 不锈钢板 ×0.05kg
│   └── 螺丝 ×4
├── 屏幕模组（采购件）×1
├── 电池（采购件）×1
└── 表带（采购件）×1
```

### 2.2 BOM 类型

| 类型 | 说明 | 用途 |
|------|------|------|
| 工程 BOM（EBOM） | 设计部门定义，产品结构视角 | 研发阶段 |
| 制造 BOM（MBOM） | 工艺部门定义，含工序和工位 | MES 生产执行 |
| 成本 BOM（CBOM） | 财务部门定义，含成本rollup | ERP 成本核算 |

### 2.3 BOM 关键属性

| 属性 | 说明 |
|------|------|
| 多级展开 | 成品 BOM 引用半成品子件，子件又有自己的 BOM |
| 版本控制 | BOM 提交后不可变，修改产生新版本 |
| 损耗率 | 每个子件的预期损耗百分比 |
| 替代料 | 某子件可用替代料生产 |
| 用料工厂 | 不同工厂可能用不同 BOM |
| 有效期 | BOM 的生效/失效日期 |

### 2.4 BOM 多级展开（MRP 核心）

```
成品 BOM（SW-001）
├── 表壳（半成品）×1
│   └── 半成品 BOM（SC-001）
│       ├── 不锈钢板 ×0.05kg
│       └── 螺丝 ×4
├── 屏幕模组 ×1
├── 电池 ×1
└── 表带 ×1

MRP 展开结果：
├── 不锈钢板: 0.05kg × 1000台 = 50kg（毛需求）
│   减去库存 10kg → 净需求 40kg → 生成采购申请
├── 螺丝: 4 × 1000台 = 4000个
│   减去库存 500个 → 净需求 3500个 → 生成采购申请
├── 屏幕模组: 1 × 1000台 = 1000个
│   减去库存 200个 → 净需求 800个 → 生成采购申请
...
```

**面试核心**：MRP 展开 = BOM 爆炸 + 净需求计算。毛需求 - 现有库存 - 在途订单 = 净需求。

## 三、工单（Work Order）

### 3.1 工单是什么

工单是 MES 的核心执行单元——它把 ERP 的"生产订单"翻译成车间可执行的任务。

| 属性 | 说明 |
|------|------|
| 工单号 | 唯一标识（如 WO-20260831-001） |
| BOM | 绑定的产品 BOM |
| 数量 | 计划生产数量 |
| 计划日期 | 计划开始/结束日期 |
| 优先级 | 紧急/普通/低 |
| 仓库 | 原料仓 → WIP 仓 → 成品仓 |

### 3.2 工单状态机

```
┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│ 已创建   │────→│ 已下达   │────→│ 已领料   │────→│ 生产中   │
│ Created  │     │ Released │     │ Issued  │     │ InProgress│
└─────────┘     └─────────┘     └─────────┘     └─────────┘
                     │               │               │
                     ▼               ▼               ▼
                ┌─────────┐    ┌─────────┐    ┌─────────┐
                │ 已暂停   │    │ 已暂停   │    │ 已完工   │
                │ Paused   │    │ Paused   │    │ Completed│
                └─────────┘    └─────────┘    └─────────┘
                                                   │
                                                   ▼
                                              ┌─────────┐
                                              │ 已入库   │
                                              │ Stored   │
                                              └─────────┘
```

### 3.3 工单核心流程

```
1. ERP 下发生产订单
        ↓
2. MES 创建工单（绑定 BOM + 数量）
        ↓
3. MRP 展开 → 生成领料清单
        ↓
4. 领料：原料仓 → WIP 仓（Stock Entry: Material Transfer）
        ↓
5. 排产：工单分配到产线/工位/时段
        ↓
6. 执行：操作员在工位上按工序加工
        ↓
7. 报工：每道工序完成后上报实际数量/耗时/不良数
        ↓
8. 质检：IPQC 过程检 / FQC 成品检
        ↓
9. 完工：WIP 仓 → 成品仓（Stock Entry: Manufacture）
        ↓
10. 回报 ERP：完工数据 + 成本数据
```

## 四、排产（Scheduling）

### 4.1 无限能力排产 vs 有限能力排产

| 维度 | 无限能力排产 | 有限能力排产（APS） |
|------|------------|-------------------|
| 假设 | 设备产能无限 | 设备产能有限 |
| 算法 | 逆向/正向排程 | 约束求解 + 启发式 |
| 复杂度 | 低 | 高 |
| 适用 | 中小企业（ERPNext 默认） | 大规模离散制造 |
| 典型工具 | ERPNext Production Plan | 自研 APS / 第三方 |

### 4.2 排产约束条件

```
排产需考虑的约束：
├── 设备约束：工位可用时段、换型时间
├── 人员约束：操作员技能、排班
├── 物料约束：原料是否到位（MRP 齐套）
├── 工艺约束：工序先后顺序、最小批量
├── 时间约束：交期、紧急插单
└── 质量约束：首批检验、SPC 监控
```

### 4.3 排产数据模型

| 实体 | 关键字段 | 说明 |
|------|---------|------|
| 排产计划 | plan_id, work_order_id, workstation_id | 工单分配到工位 |
| 排产时段 | slot_id, start_time, end_time | 时间窗口 |
| 产能日历 | calendar_id, date, available_hours | 工位可用时间 |
| 换型时间 | changeover_id, from_product, to_product | 换型耗时 |

## 五、质量管理

### 5.1 三检制

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│ IQC     │────→│ IPQC    │────→│ FQC     │
│ 来料检   │     │ 过程检   │     │ 成品检   │
│ 供应商来料 │    │ 生产过程中 │    │ 入库前   │
└─────────┘     └─────────┘     └─────────┘
```

| 检验类型 | 时机 | 检验对象 | 不合格处置 |
|---------|------|---------|-----------|
| IQC | 采购入库时 | 原材料/零部件 | 退货/让步接收/挑选使用 |
| IPQC | 工序流转时 | 在制品 | 返工/返修/报废 |
| FQC | 完工入库前 | 成品 | 返工/降级/报废 |

### 5.2 质检模板

| 检验项目 | 标准值 | 上限 | 下限 | 检验方法 |
|---------|--------|------|------|---------|
| 尺寸 A | 10.0mm | 10.1mm | 9.9mm | 卡尺 |
| 外观 B | 无划痕 | - | - | 目视 |
| 功能 C | 通过 | - | - | 测试台 |

### 5.3 质量数据模型

| 实体 | 关键字段 | 说明 |
|------|---------|------|
| 质检模板 | template_id, name, items[] | 检验项定义 |
| 质检单 | inspection_id, type(IQC/IPQC/FQC), result | 一次检验记录 |
| 质检明细 | detail_id, inspection_id, item_name, actual, standard | 每项检验结果 |
| 不合格品 | nc_id, inspection_id, defect_type, disposition | 不合格品处置 |

## 六、设备管理

### 6.1 OEE 计算

```
OEE = 可用率 × 性能率 × 质量率

可用率 = 实际运行时间 / 计划运行时间
       = (计划时间 - 停机时间) / 计划时间

性能率 = 实际产出 / 理论产出
       = (实际产出 × 标准节拍) / 实际运行时间

质量率 = 良品数 / 总产出

示例：
  计划运行 8h = 480min
  停机 60min → 实际运行 420min
  可用率 = 420/480 = 87.5%
  理论产出 = 420min / 2min/件 = 210件
  实际产出 = 200件
  性能率 = 200/210 = 95.2%
  良品 = 195件
  质量率 = 195/200 = 97.5%
  OEE = 87.5% × 95.2% × 97.5% = 81.2%
```

**世界级 OEE > 85%**，一般制造业 60% 左右。

### 6.2 设备管理模块

| 功能 | 说明 |
|------|------|
| 设备档案 | 设备编码、型号、位置、供应商、购入日期 |
| 点检 | 日常检查清单，操作员定时执行 |
| 保养 | 定期保养计划（日/周/月/年） |
| 故障维修 | 故障报修 → 维修工单 → 维修记录 |
| 备件管理 | 备件库存、领用、采购 |

## 七、面试建模题

### Q1：如何设计工单的状态机？

**考察点**：状态机设计能力 + 业务理解

**参考答案**：

工单状态机需要覆盖完整生命周期，关键状态包括：Created（已创建）→ Released（已下达）→ Issued（已领料）→ InProgress（生产中）→ Completed（已完工）→ Stored（已入库）。

设计要点：
1. **状态不可跳跃**：已创建不能直接到生产中，必须先下达和领料
2. **暂停/恢复**：任何执行中状态都可暂停，恢复后回到原状态
3. **异常状态**：设备故障、质量异常时可进入"异常挂起"状态
4. **状态转换必须有操作记录**：谁、什么时间、做了什么操作
5. **完工必须校验**：实际产出 + 不良数 ≤ 领料数量（防超产）

### Q2：BOM 多级展开在数据库中如何实现？

**考察点**：递归查询 + 数据库设计

**参考答案**：

方案一：邻接表（简单但递归查询慢）
```sql
-- BOM 表
CREATE TABLE mes_bom_item (
    id BIGINT PRIMARY KEY,
    parent_item_id BIGINT,  -- 父件
    child_item_id BIGINT,   -- 子件
    quantity DECIMAL(10,4),  -- 用量
    scrap_rate DECIMAL(5,4) -- 损耗率
);
-- 递归 CTE 展开
WITH RECURSIVE bom_tree AS (
    SELECT * FROM mes_bom_item WHERE parent_item_id = ?
    UNION ALL
    SELECT b.* FROM mes_bom_item b
    JOIN bom_tree t ON b.parent_item_id = t.child_item_id
)
SELECT * FROM bom_tree;
```

方案二：闭包表（查询快但写入复杂）
```sql
-- 记录所有祖先-后代关系
CREATE TABLE mes_bom_closure (
    ancestor_id BIGINT,
    descendant_id BIGINT,
    depth INT
);
```

推荐方案一（邻接表 + 递归 CTE），MySQL 8.0+ 和 PostgreSQL 都支持。
