> Redis 是后端面试中与 MySQL 并列的**必考中间件**，缓存、锁、限流、Session 几乎无处不现。

## 什么是 Redis？

Redis（Remote Dictionary Server）是一个开源的**基于内存的键值存储系统**，官方自称"Data Structure Server"——因为它不只是一个 KV 缓存，而是一个**数据结构服务器**：

- **5 大数据结构**：String / List / Hash / Set / ZSet（有序集合）
- **进阶结构**：Bitmap / HyperLogLog / GEO / Stream
- **单线程 + 多路复用**：10 万+ QPS，IO 线程池只是辅助
- **持久化**：RDB 快照 + AOF 日志，数据可恢复
- **高可用**：主从复制、Sentinel 哨兵、Cluster 集群
- **生态完善**：Lua 脚本、Redisson 客户端、Spring Cache 整合

一句话概括：**MySQL 管"存得住"，Redis 管"拿得快"，两者构成互联网后端最经典的冷热数据架构。**

## Redis 在 AI 商城的角色

AI 商城（mall-micro-cloud）里，Redis 几乎是"无处不在"：

| 场景 | Redis 用法 | 相关数据结构 |
|------|-----------|-------------|
| 商品缓存 | 商品详情多级缓存（Caffeine 本地 + Redis），QPS 提升百倍 | Hash / String |
| 秒杀库存预扣 | 高并发下用 Redis 原子扣减库存，MQ 异步落库 | String + Lua |
| 分布式 Session | 多个微服务共享用户登录态（Spring Session） | Hash + 过期 |
| 计数器 | 访问量统计、限流令牌桶、热搜词排行 | String / ZSet / INCR |
| 购物车 | 用户购物车（userId → 商品 Map） | Hash |
| 接口幂等 | 下单防重，setIfAbsent 30 秒 | String + SETNX |
| 排行榜 | 商品热度榜、秒杀活动榜单 | ZSet |
| 布隆过滤器 | 防缓存穿透，过滤不存在的商品 ID | Bitmap |

> Redis 在商城中解决的核心矛盾：**数据库磁盘 IO 慢 vs 用户要毫秒级响应**。读多写少的数据放 Redis，写多的一致性数据仍以 MySQL 为准。

## 三个贯穿全文的核心思想

1. **缓存是"性能"，数据库是"真相"**：Redis 可以丢（可持久化尽量少丢），MySQL 不能丢——一切以"最终一致性"兜底。
2. **单线程是特性不是缺陷**：正因为单线程执行命令，Lua 脚本才能成为天然原子操作，分布式锁才得以实现。
3. **面试考的是"取舍"**：数据结构选型、缓存策略选择、高可用架构选型，本质都是权衡——先想清楚业务场景，再谈技术方案。

> 让我们从快速入门开始：用 Docker 启动 Redis，把 5 大基础数据结构全部敲一遍。
