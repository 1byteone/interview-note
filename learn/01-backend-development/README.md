# 后端开发总纲 — 架构设计 · API 设计 · 分层模式

> 本模块是 16 个技术栈学习体系中的**第一个技术栈**，也是整个后端知识体系的基石。
> 无论你最终走向微服务、高并发还是架构师岗位，本节的内容都会反复出现。

---

## 什么是后端开发？

后端开发（Backend Development）负责处理**用户看不到但必须正确**的那部分：接收请求、执行业务逻辑、读写数据、返回响应。它关注的是：

- **架构设计**：系统如何拆分、模块如何组织、演进路径如何规划
- **API 设计**：对外暴露什么样的契约，如何保证稳定、安全、易用
- **分层模式**：业务代码如何组织，如何让代码可读、可测、可维护
- **数据与性能**：如何与数据库交互，如何在流量增长时保持可用

一句话概括：**前端负责"看得见"，后端负责"撑得住"。**

本技术栈围绕一条主线展开：**从单体到微服务的架构演进 → 规范的 API 设计 → 经典的分层实现 → 结合 AI 商城项目落地**。

## 三个贯穿全文的核心思想

1. **演进优于重建**：架构没有银弹，单体不是错误，微服务不是万能药，关键是识别演进时机。
2. **契约就是产品**：API 是后端对外的产品，它的稳定性、可读性、安全性直接影响整个系统的质量。
3. **分层保证秩序**：三层乃至六边形架构解决的都是同一个问题——让业务核心不被技术细节污染。
