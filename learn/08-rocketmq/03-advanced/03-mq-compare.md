# RocketMQ vs Kafka vs RabbitMQ

> 三大主流消息队列的全面对比与选型依据，以及 AI 场景下的选型建议。
> 面试必问：为什么选 RocketMQ 而不是 Kafka？两者在事务、顺序、堆积上的差异。

---

## 1. 三款 MQ 核心定位

| 维度 | RocketMQ | Kafka | RabbitMQ |
|------|----------|-------|----------|
| 开发语言 | Java | Scala/Java | Erlang |
| 开源组织 | Apache（源于阿里巴巴） | Apache（源于 LinkedIn） | Pivotal/VMware |
| 核心定位 | 金融级可靠消息 + 业务解耦 | 高吞吐日志/流处理 | 灵活路由、复杂消息模式 |
| 单机吞吐 | 十万级 TPS | 百万级 TPS | 万级 TPS |
| 延迟 | 毫秒级 | 毫秒级（但批量攒批） | 微秒级 |

---

## 2. 功能特性全面对比

| 特性 | RocketMQ | Kafka | RabbitMQ |
|------|----------|-------|----------|
| **事务消息** | ✅ 支持（半消息+回查） | ❌ 事务仅支持生产者本地事务，无消息级事务 | ⚠ 依赖插件，弱 |
| **消息轨迹** | ✅ 原生支持 | ❌ 需要额外插件 | ⚠ 插件支持 |
| **延迟消息** | ✅ 18 个延迟等级 | ❌ 不原生支持 | ✅ 插件支持 |
| **顺序消息** | ✅ 分区顺序 + 全局顺序 | ✅ 分区顺序 | ⚠ 单队列顺序 |
| **消息过滤** | ✅ Tag + SQL92 | ❌ 仅消费端过滤 | ✅ 路由规则灵活 |
| **死信队列** | ✅ 原生支持 | ❌ 需要手动实现 | ✅ 原生支持 |
| **消息重试** | ✅ 16 次递增 | ⚠ 手动设置重试 | ✅ 原生支持 |
| **消息追溯** | ✅ 支持按时间点消费 | ✅ 支持 | ❌ 不支持 |
| **管理界面** | ✅ 官方控制台 | ⚠ 常用第三方（如 Kafdrop） | ✅ 官方管理界面 |

## 3. 性能与可靠性对比

### 3.1 性能对比

| 指标 | RocketMQ | Kafka | RabbitMQ |
|------|----------|-------|----------|
| 单机吞吐 | 10万+ TPS | 100万+ TPS | 1万+ TPS |
| 延迟 | 2-5ms | 几ms（批量时稍高） | 微秒级 |
| 消息堆积 | 亿级 | 亿级 | 百万级（有内存限制） |
| 存储方式 | 顺序写文件 + 索引 | 顺序写日志（Segment） | 内存优先 + 惰性队列 |

**关键差异**：
- **Kafka 强在吞吐**：零拷贝（Zero-Copy）、批量压缩、PageCache 优化，适合海量日志与流式数据
- **RocketMQ 强在功能**：事务消息、延迟消息、死信队列、消息轨迹开箱即用
- **RabbitMQ 强在路由**：AMQP 协议原生支持 Exchange/Binding/Routing Key，复杂路由灵活

### 3.2 可靠性对比

| 环节 | RocketMQ | Kafka | RabbitMQ |
|------|----------|-------|----------|
| 生产确认 | ACK 机制 | ACK 机制 | Publisher Confirm |
| 刷盘 | 同步/异步可配 | 同步/异步可配 | 内存/磁盘可配 |
| 多副本 | Dledger（Raft） | ISR（副本同步） | 镜像队列 |
| 消费确认 | 手动/自动提交 offset | 手动/自动提交 offset | 手动/自动 ACK |
| 消息不丢失 | 高（配置项齐全） | 高（需合理配置） | 高 |

## 4. 架构差异

### 4.1 RocketMQ 架构（Topic/Queue 模型）

```
NameServer ── 路由发现
     │
   Broker ── 存储（CommitLog 顺序写 + ConsumeQueue 索引）
     │
 Topic └── Queue 0 ── Queue 1 ── Queue 2（横向扩展，多个 Queue 并行）
```

### 4.2 Kafka 架构（Topic/Partition 模型）

```
ZooKeeper / KRaft ── 元数据管理
     │
  Broker ── 存储（Segment 日志文件）
     │
 Topic └── Partition 0 ── Partition 1 ── Partition 2（分区 + 副本 ISR）
```

**核心差异**：
- Kafka 的 Partition 即物理分区，每条消息按 key hash 到固定 Partition
- RocketMQ 的 Queue 在磁盘上是单文件（CommitLog）+"逻辑队列"（ConsumeQueue）
- RocketMQ 存储模型天然支持**任意时间点回溯消费**（从任意 offset 读取），Kafka 只能从最近的 offset 消费

### 4.3 RabbitMQ 架构（Exchange 路由模型）

```
Exchange ── Binding ── Queue 0
    │          ├────── Queue 1
    │          └────── Queue 2（灵活路由）
  生产者发到 Exchange → 根据 RoutingKey 路由到绑定队列
```

## 5. 选型依据

### 5.1 选型决策树

```
需要消息中间件？
├── 需要事务消息 / 延迟消息 / 死信队列？
│   ├── 是 → RocketMQ
│   └── 否 ↓
├── 需要百万级高吞吐（日志/流处理）？
│   ├── 是 → Kafka
│   └── 否 ↓
├── 需要复杂路由（Topic 按 RoutingKey 分发）？
│   ├── 是 → RabbitMQ
│   └── 否 ↓
└── 业务场景 → RocketMQ（Java 生态最佳选择）
```

### 5.2 不同场景的推荐

| 场景 | 推荐 | 原因 |
|------|------|------|
| **Java 微服务业务解耦** | RocketMQ | 事务消息、死信、轨迹全支持，Java 生态 |
| **金融支付场景** | RocketMQ | 严格的消息可靠性与事务保证 |
| **日志收集/流处理** | Kafka | 高吞吐、支持流处理（Kafka Streams） |
| **用户行为埋点/推荐** | Kafka | 海量数据 + 实时计算链路 |
| **复杂路由场景** | RabbitMQ | AMQP 协议灵活路由 |
| **小团队快速起步** | RocketMQ | 单机部署快，功能全面 |

## 6. AI 场景下的消息队列选择

### 6.1 AI 商城的典型消息场景

| 场景 | 推荐 | 原因 |
|------|------|------|
| 订单异步处理 | **RocketMQ** | 事务消息 + 幂等消费 |
| 秒杀削峰 | **RocketMQ** | 消息轨迹 + 消费限流 + 大规模堆积 |
| 订单超时 | **RocketMQ** | 延迟消息开箱即用 |
| AI 推荐日志 | **Kafka** | 用户行为埋点量大，Kafka 高吞吐 |
| AI 训练数据采集 | **Kafka** | 海量数据实时采集 + 流式处理 |
| 库存扣减 | **RocketMQ** | 需要事务消息保证最终一致 |
| 站内信/通知 | RabbitMQ/RocketMQ | 均适合，按团队习惯 |

### 6.2 AI 推荐场景的混合架构

```
┌─────────────────────────────────────────────────┐
│            AI 商城消息架构                        │
│                                                 │
│  Kafka  ←── 用户行为埋点（点击/搜索/购买）        │
│   │            ↓ 流处理（Flink）                 │
│   │            ↓ 生成实时特征 → 推荐引擎          │
│                                                 │
│  RocketMQ ←── 订单、支付、库存（业务事务链）      │
│              秒杀削峰 → 异步库存扣减              │
│                                                 │
│  RabbitMQ ←── 站内信、邮件、短信（灵活路由）      │
└─────────────────────────────────────────────────┘
```

### 6.3 为什么 AI 商城主推 RocketMQ

1. **事务消息**：下单 + 扣库存 + 积分发放的分布式事务最终一致性
2. **削峰填谷**：秒杀场景下需求峰值流量缓冲能力
3. **消息轨迹**：排查问题速度快，官方控制台开箱即用
4. **Java 技术栈**：与 Spring Boot 生态无缝集成（rocketmq-spring-boot-starter）
5. **阿里云产品化**：RocketMQ 在云厂商（阿里云）有企业版支持

本章你学会了：

- RocketMQ / Kafka / RabbitMQ 三大 MQ 的核心定位与功能差异
- 性能、可靠性、架构层面的关键区别
- 基于业务场景的选型决策树
- AI 商城场景下的混合消息架构

**一句话总结**：Java 业务场景选 RocketMQ（事务、顺序、功能全），日志流处理选 Kafka（吞吐之王），灵活路由选 RabbitMQ（AMQP 协议）。
